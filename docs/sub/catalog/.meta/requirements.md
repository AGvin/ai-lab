# Documentation Requirements

## Requirements

- Present `catalog/` as the canonical entry point for identifiable AI Lab ecosystem entities and formal specification artifacts/contracts.
- Explain that catalog nodes own stable entity/specification identity and source-backed facts or normative artifact contracts, while reusable abstract concepts, learning material, project policies, reader journeys, and other non-catalog knowledge belong to their separate canonical owners.
- Render the standard child-navigation block from the validated direct-child projection so every currently materialized direct catalog domain appears exactly once.
- Keep the introduction concise and descriptive; exhaustive physical hierarchy belongs to the Documentation Tree and detailed navigation belongs to child indexes.
- Do not imply that an empty or thin child domain is complete merely because its index exists; catalog materialization remains evidence-driven and incremental.

## Validation

- The page contains no temporary-placeholder notice.
- The child-navigation block matches the validated materialized direct-child projection and every destination resolves to a direct child of `catalog/`.
- The page does not duplicate the complete descendant taxonomy.
- The page does not absorb reusable abstract concepts, learning, project policy, or other non-catalog documentation ownership.
