# Documentation Requirements

## Requirements

- Present `physical-ai-and-robotics/` as the canonical software owner for self-managed products whose primary identity is simulation, training, evaluation, control, or runtime integration for embodied AI systems interacting with physical environments or robots.
- Allow physically based simulation, synthetic robot data generation, reinforcement/imitation learning, perception/control integration, sim2real/real2sim workflows, and deployment to physical robots when those stages belong to one embodied-AI product identity.
- Exclude generic robotics middleware without a material first-class AI/ML role, general-purpose game engines used incidentally for simulation, generic physics solvers without an embodied-learning identity, robot hardware, robotics datasets/models, and generic inference runtimes merely deployed on robots.
- Keep the category flat until materialized density creates a genuine canonical-placement problem between simulation, robot learning, and runtime/middleware.

## Validation

- Children are embodied-AI/robotics-first software identities.
- Generic robotics or physics tooling is not included solely because AI systems can use it.
- Navigation matches validated materialized direct children.
