# Documentation Requirements

## Requirements

- Identify Temporal as an open-source durable-execution platform for reliable long-running application workflows that persist progress and resume after failures.
- Preserve its primary placement under `workflow-engines/application-orchestration`; Temporal coordinates application workflow code through a service/worker model rather than acting as a data-pipeline-only scheduler.
- Distinguish self-hosted Temporal Server software from Temporal Cloud and separately operated service features.
- Keep SDK support, deployment topology, persistence stores, workflow semantics, cloud features, and other mutable implementation details source-backed when expanded.
- Include current official Temporal documentation and repository references.

## Validation

- The page preserves the durable-execution/service-worker boundary.
- Self-hosted Temporal Server and Temporal Cloud are not conflated.
- Official resource links match canonical entity metadata.
- The page contains no temporary-placeholder wording.
