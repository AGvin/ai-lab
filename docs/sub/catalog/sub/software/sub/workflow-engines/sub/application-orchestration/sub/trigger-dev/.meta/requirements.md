- Identify Trigger.dev as an open-source framework/platform for reliable background jobs, scheduled tasks, long-running workflows, and AI-oriented asynchronous application work.
- Preserve its primary placement under `workflow-engines/application-orchestration`; tasks run application code with durable/retry/observability infrastructure rather than defining a data-pipeline-specific DAG system.

- Keep runtime support, machine/execution features, wait/checkpoint behavior, hosting architecture, and other mutable details source-backed when expanded.
- Include current official Trigger.dev documentation and repository references.
