# Documentation Requirements

## Requirements

- Identify Apache Burr as an open-source Python framework for building applications as explicit state machines with actions, transitions, persisted state, and observability.
- Preserve its primary placement under `workflow-engines/application-orchestration`; Burr can support conversational, agentic, and non-LLM stateful applications without becoming a general agent framework.
- Preserve DAGWorks as Burr's origin company while keeping that provenance distinct from the project's current Apache Software Foundation incubation and governance boundary.
- Preserve the distinction between state-machine application orchestration and external durable-execution services such as Temporal or Restate.
- Render the standard `entity-relations` block from the validated current-entity relation projection.
- Keep persistence backends, integrations, UI/telemetry features, incubation status, and other mutable implementation details source-backed when expanded.
- Include current official Apache Burr documentation, repository, and provenance references.

## Validation

- The page presents Burr as a state-machine application framework rather than as a generic workflow scheduler or model provider.
- DAGWorks origin is not conflated with current Apache governance or sole maintenance.
- Agent use cases are treated as applications of the framework, not its only identity.
- The `entity-relations` block matches the validated current-entity relation projection and every rendered destination resolves to a canonical node.
- Official resource links match canonical entity metadata.
- The page contains no temporary-placeholder wording.
