# Documentation Requirements

## Requirements

- Identify OpenSpec as a lightweight spec-driven development framework for aligning humans and AI coding assistants on intended behavior before and during implementation.
- Preserve the distinction between current system specifications and proposed change artifacts; describe the workflow as iterative rather than a rigid waterfall gate.
- Preserve its primary placement under `development-tools/spec-driven-development`; tool integrations and generated assistant commands are delivery mechanisms rather than a separate agent-product identity.
- Render the standard `entity-relations` block from the validated current-entity relation projection.
- Keep exact commands, supported-tool inventory, workflow profiles, telemetry behavior, and version-specific configuration source-backed when expanded.
- Include current official OpenSpec site and repository references.

## Validation

- The page characterizes OpenSpec as a specification/change workflow rather than a coding agent or implementation runtime.
- The page does not present the workflow as phase-locked when current OpenSpec supports iterative artifact updates.
- Official resource links match canonical entity metadata.
- The page contains no temporary-placeholder wording.
- The `entity-relations` block matches the validated current-entity relation projection and every rendered destination resolves to a canonical node.
