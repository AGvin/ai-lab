# Documentation Requirements

## Requirements

- Present AMD Ross as AMD's released client-agnostic agentic development assistant/productivity layer for natural-language workflows across AMD Embedded tools from design and optimization through debugging and deployment.
- Preserve the product boundary across AMD-provided MCP servers, trusted/local knowledge-base options, expert-authored Agent Skills, design examples, and optional VS Code packaging without splitting each component into a peer software product by default.
- Keep Vivado, Vitis, supported IDE/CLI clients, preferred third-party/local LLMs, embedding models, and Agent Skills/MCP standards as dependencies/integrations rather than AMD Ross-owned identities.
- Preserve the client-agnostic/no-separate-answer-model boundary: Ross can operate through supported IDE/CLI clients and a user-selected LLM rather than being one trained model.
- Treat supported AMD tool versions, MCP-server inventory, skills/design examples, knowledge-base packaging, client compatibility, monthly release cadence, air-gapped setup, download artifacts, and licensing prerequisites as freshness-sensitive.
- Render the standard `entity-relations` block from validated current-entity relations.

## Validation

- AMD Ross remains agentic development software rather than a trained model or hosted assistant service.
- MCP servers, skills, and knowledge-base artifacts are not duplicated automatically as peer products.
- Producer provenance resolves bidirectionally to Advanced Micro Devices, Inc.
