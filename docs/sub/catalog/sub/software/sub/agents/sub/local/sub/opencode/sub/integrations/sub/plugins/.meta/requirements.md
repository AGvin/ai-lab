# Documentation Requirements

## Requirements

- Document OpenCode-specific plugin support as mutable software/product facts from current official OpenCode documentation.
- Cover current local/package-based discovery and loading, configuration, plugin functions/hooks, ordering, package dependencies, permissions/security-relevant behavior, and compatibility only when source-backed.
- Keep exact directories, configuration keys, package conventions, load order, hook/event surfaces, commands, and compatibility current-source-backed because they may change.
- Distinguish OpenCode's product-specific plugin mechanism from the vendor-neutral Agent Plugins standard unless official OpenCode documentation explicitly states conformance/interoperability.
- Keep generic plugin concept, lifecycle, trust, adoption, and portability teaching with selected concept/learning owners.

## Validation

- Current OpenCode plugin behavior is supported by current official OpenCode documentation.
- Product-specific behavior is not presented as portable Agent Plugins specification truth.
- Generic plugin pedagogy is not duplicated.
