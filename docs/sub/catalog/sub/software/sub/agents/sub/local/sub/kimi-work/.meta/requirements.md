# Documentation Requirements

## Requirements

- Present Kimi Work as Moonshot AI's released beta local desktop agent for knowledge workers, running agent actions against user-controlled local files, browser sessions, code execution, plugins/skills and scheduled workflows on supported Mac/Windows clients.
- Preserve local-agent placement even though model inference and some connected services can be cloud-backed: the durable product job is acting on the user's local desktop/workspace and files.
- Keep Kimi hosted assistant, Kimi Code, Kimi Claw, Kimi models, Kimi Browser Extension/WebBridge, plugins and skills as separate products/integrations rather than peer identities inside Kimi Work.
- Preserve the documented permission modes and trust boundary around reading/writing local files, code execution, system changes, browser automation, imported browser sessions/cookies, scheduled tasks and fully automatic execution.
- Preserve beta lifecycle explicitly and keep supported OS/hardware, release versions, model defaults, plugins, Agent Swarm limits, browser behavior, local directories and plan/credit rules freshness-sensitive.
- Render the standard `entity-relations` block from validated current-entity relations.

## Validation

- Kimi Work remains local desktop-agent software rather than a hosted workspace simply because inference can be remote.
- Permission modes are not described as eliminating execution risk.
- Producer provenance resolves bidirectionally to Moonshot AI.
