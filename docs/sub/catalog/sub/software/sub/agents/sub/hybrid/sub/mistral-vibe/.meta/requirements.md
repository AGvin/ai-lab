# Documentation Requirements

## Requirements

- Identify Mistral Vibe as Mistral AI's unified agent product for professional productivity and coding across web, mobile, VS Code, terminal/CLI, and managed remote-agent surfaces.
- Preserve the current product consolidation boundary: Le Chat has become Vibe, and current first-party documentation presents Chat/Work as one Vibe experience with Work and Code as task modes/surfaces rather than separate peer product identities.
- Keep the Hybrid Agent classification source-backed: Vibe exposes installable/user-controlled CLI and editor workflows with local repository, shell, filesystem, and tool access while also supporting Mistral-operated remote coding agents, web/mobile Work execution, scheduled/background tasks, and cloud sandboxes.
- Preserve the distinction between local CLI/editor execution and managed remote/cloud execution; local tool execution does not imply that model inference, connectors, remote tasks, or relevant context remain local.
- Keep Vibe Work, Vibe Code, legacy Le Chat naming, Code Web, remote agents, VS Code extension, CLI, skills, connectors, workflows, knowledge base, Canvas, scheduled tasks, and similar named capabilities as surfaces of the same Vibe product unless later lifecycle establishes an independently useful canonical product boundary.
- Keep Mistral Studio, Admin, Forge, Search Toolkit, underlying Mistral models, and third-party connectors/services with their own current or future canonical owners rather than folding them into Vibe identity.
- Preserve trust boundaries around repository/workspace access, shell commands, generated diffs, browser/web content, connected applications, credentials, skills, remote-agent actions, scheduled tasks, and external side effects; approval and sandbox controls reduce risk but are not universal correctness or security guarantees.
- Treat supported models, plan eligibility, credits/limits, connector inventory, skill/workflow behavior, knowledge/memory features, operating systems, extension/CLI versions, cloud-sandbox availability, preview features, retention/data controls, and security advisories as freshness-sensitive.
- Render the standard `entity-relations` block from the validated current-entity relation projection.

## Validation

- Vibe is represented as one hybrid agent product rather than duplicated into Le Chat, Work, Code, CLI, editor, or remote-agent peer identities.
- Local and Mistral-managed execution surfaces are not conflated.
- A preview feature inside Vibe does not make the already released/GA Vibe product itself preview-only.
- Producer provenance resolves bidirectionally to Mistral AI.
