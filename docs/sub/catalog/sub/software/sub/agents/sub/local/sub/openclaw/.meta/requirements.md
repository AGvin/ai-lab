# Documentation Requirements

## Requirements

- Identify OpenClaw as a self-hosted personal AI assistant designed to run on the user's own devices or infrastructure.
- Preserve the product boundary that the Gateway is a user-operated control plane connecting the assistant to messaging/channel surfaces, tools, skills, sessions, memory, and agent workflows.
- Preserve multi-channel and model-provider flexibility at a high level without freezing current channel/provider counts.
- Do not misclassify OpenClaw as a hosted assistant service merely because it integrates remote messaging or model services.
- Keep foundation/governance details, platform inventories, runtime versions, provider lists, and other mutable state source-backed when expanded.
- Include the current official OpenClaw repository and site.

## Validation

- The page distinguishes the OpenClaw assistant from its Gateway control-plane component.
- The profile preserves self-hosted/user-controlled execution as the primary ownership boundary.
- Mutable integration counts are not treated as stable identity facts.
