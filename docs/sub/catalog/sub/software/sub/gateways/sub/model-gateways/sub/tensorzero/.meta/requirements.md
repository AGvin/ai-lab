# Documentation Requirements

## Requirements

- Identify TensorZero as an open-source LLMOps stack that unifies an LLM gateway with observability, evaluation, experimentation, and optimization.
- Explain that the model-gateway placement reflects the gateway as the central inference/request path and feedback collection point, not a claim that TensorZero is only a router.
- Cover routing, model/provider abstraction, observability, feedback, evaluations, experiments, and optimization workflows only when current upstream sources support them.
- Distinguish TensorZero from hosted-only gateways and from observability platforms whose primary identity does not sit in the model request path.
- Keep supported providers, deployment modes, APIs, optimization methods, and release state freshness-sensitive.

- Preserve the lifecycle verified on October 17, 2026: the official website states that TensorZero is no longer maintained; code remains available and the first-party repository is archived. Do not present it as an actively maintained peer or infer a shutdown date or successor.
- Explain the adoption consequence: assess dependency/security maintenance, operating ownership and migration needs independently; historical feature descriptions and enterprise terms do not establish current upstream updates or support.
- Preserve TensorZero, Inc. as the historical direct software producer with exact `produced-by` / `produces` reciprocity, separately from current maintenance availability.
- Render the standard `entity-relations` block and include the official lifecycle statement, repository and company terms.

## Validation

- TensorZero's broader LLMOps identity is not erased by gateway placement.
- The page does not duplicate TensorZero under evaluation-and-observability.
- The reader states the unmaintained/archived boundary without implying corporate dissolution.
- The direct producer resolves to `catalog/producers/t/tensorzero-inc` with an exact reciprocal software target.
