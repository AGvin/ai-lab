# Documentation Requirements

## Requirements

- Present Vector Search as the canonical data-infrastructure group for self-managed software whose primary role is vector storage, indexing, similarity search, or retrieval.
- Render the standard child-navigation block from the validated direct-child projection so every materialized direct child appears exactly once.
- Group products by operational role rather than packaging form, so standalone systems and database extensions can coexist without becoming separate taxonomy axes.
- Keep framework-layer retrieval orchestration and hosted-only managed vector services outside this software group.

## Validation

- The child-navigation block matches the validated materialized direct-child projection.
- Product-specific deployment, indexing, database, and API details remain with the child profiles.
- The page contains no temporary-placeholder wording.
