# Documentation Requirements

## Requirements

- Identify LanceDB OSS as the independently released, open-source embedded retrieval and data platform with a durable role in vector search, keyword/full-text search, and multimodal retrieval.
- Preserve primary catalog ownership under `software/data-infrastructure/vector-search`; its Lance format foundation, columnar storage, multimodal lakehouse functions, and SDKs remain additional capabilities rather than separate materialized peers by default.
- Keep LanceDB OSS distinct from LanceDB Enterprise and hosted/managed LanceDB offerings; licensing, deployment and API compatibility may differ materially.
- Treat performance, vector-search index and filtering capabilities, table format/schema/versioning features, library APIs, language clients, data-size claims, and optional GPU support as freshness-sensitive.
- Attribute published benchmarks to exact software revision, data, hardware, index type, workload and measurement methodology, not a universal throughput guarantee.
- Reconcile LanceDB producer provenance with a reciprocal producer relation.

## Validation

- The independently released self-managed/OSS identity is not conflated with managed provider services or ancillary SDK/CLI features.
- Current source references and producer provenance resolve to the correct canonical owners.
- Mutable performance, service feature, and compatibility claims remain scoped to verifiable release/workload configurations.
- Reciprocal producer relation is present and matches the entity identity.
