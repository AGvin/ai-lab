# Documentation Requirements

## Requirements

- Identify Obsidian as a local-first knowledge-base/workspace application built around Markdown-formatted plain-text notes stored in vault folders on the user's file system.
- Preserve its placement under `interfaces-and-workspaces/knowledge-workspaces`; plugins, automation, AI features, CLI access, or direct agent edits to vault files are secondary capabilities rather than backend-infrastructure identity.
- Preserve Dynalist Inc. as the legal organization behind Obsidian while keeping the product identity distinct.
- Render the standard `entity-relations` block from the validated current-entity relation projection.
- Preserve the boundary between local vault data and optional synchronization or publishing services.
- Keep mutable platform, plugin, Sync, Publish, licensing, and account details source-backed when expanded.
- Include current official Obsidian site, Help, and legal references.

## Validation

- The page presents Obsidian as a user-facing knowledge workspace rather than agent memory infrastructure.
- Local Markdown/vault ownership is described without implying that synchronization is required.
- The `entity-relations` block matches the validated current-entity relation projection and every rendered destination resolves to a canonical node.
- Official resource links match canonical entity metadata.
- The page contains no temporary-placeholder wording.
