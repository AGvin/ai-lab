# Documentation Requirements

## Requirements

- Identify n8n as a fair-code workflow and integration automation platform that combines visual workflow construction, custom code/logic, integrations, and native AI capabilities.
- Preserve its primary placement under `automation/integration-automation`; AI-agent and agentic-workflow features are capabilities of the broader automation platform rather than a reason to classify n8n primarily as agent software.
- Explain that n8n can build AI-agent and agentic workflows, including tool-connected, multi-step, and multi-agent patterns where supported by current upstream capabilities.
- Preserve the distinction between self-hosted/user-controlled n8n software and n8n Cloud or other separately operated service surfaces.
- Use current upstream fair-code/source-available licensing terminology and do not describe n8n as OSI-open-source unless upstream licensing materially changes.
- Keep AI workflow-builder/assistant availability, integration counts, edition-specific features, supported runtime details, pricing, quotas, and release-specific capabilities source-backed and time-bounded when expanded.
- Render the standard `entity-relations` block from the validated current-entity relation projection.
- Include current official n8n site, documentation, and repository references.

## Validation

- The page uses current fair-code/source-available licensing language rather than incorrectly calling n8n open source.
- AI-agent and agentic-workflow capabilities are visible without replacing integration automation as the primary identity.
- Self-hosted and cloud operating boundaries are not conflated.
- Mutable AI workflow-builder/assistant availability is not presented as a timeless universal capability without qualification.
- Official resource links match canonical entity metadata.
- The page contains no temporary-placeholder wording.
- The `entity-relations` block matches the validated current-entity relation projection and every rendered destination resolves to a canonical node.
