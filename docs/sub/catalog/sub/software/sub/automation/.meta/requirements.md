# Documentation Requirements

## Requirements

- Present Automation as the canonical software catalog index for products that connect services, trigger actions, execute scripts, and automate operational or development processes without being general AI workflow engines.
- List every materialized direct child exactly once.
- Preserve the distinction between integration automation and developer automation while keeping product-specific behavior with child profiles.
- Do not reproduce or depend on legacy `catalog-item`, `catalog-index`, `common/index`, or `catalog/item` selectors.

## Validation

- Navigation matches the materialized direct children.
- The page remains category-level and does not duplicate concrete automation products.
- The page contains no temporary-placeholder wording.
