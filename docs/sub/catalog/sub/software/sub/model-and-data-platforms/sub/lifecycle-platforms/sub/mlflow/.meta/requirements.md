# Documentation Requirements

## Requirements

- Identify MLflow as an open-source AI engineering and lifecycle platform covering agents/LLM applications as well as traditional ML models.
- Preserve its primary placement under `model-and-data-platforms/lifecycle-platforms`; experiment tracking, tracing, evaluation, prompt management, model registry, deployment, and AI-gateway capabilities are integrated platform surfaces rather than reasons to duplicate MLflow across observability or gateway categories.
- Preserve Databricks, Inc. as MLflow's origin producer while keeping current Linux Foundation open governance distinct from original production and from Databricks-managed MLflow offerings.
- Distinguish open-source MLflow from managed MLflow offerings such as Databricks-hosted platform surfaces.
- Render the standard `entity-relations` block from the validated current-entity relation projection.
- Keep API/version behavior, managed integrations, supported model/application frameworks, governance details, and other mutable details source-backed when expanded.
- Include current official MLflow documentation, repository, and provenance references.

## Validation

- The page reflects current agents/LLMs and ML-model lifecycle scope rather than legacy experiment-tracking-only positioning.
- Databricks origin is not conflated with current Linux Foundation governance or a claim that Databricks alone maintains the open-source project.
- MLflow is not duplicated under evaluation/observability or gateways solely because those capabilities exist.
- The `entity-relations` block matches the validated current-entity relation projection and every rendered destination resolves to a canonical node.
- Official resource links match canonical entity metadata.
- The page contains no temporary-placeholder wording.
