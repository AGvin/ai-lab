# Documentation Requirements

## Requirements

- Identify Label Studio as an open-source data-labeling platform for annotating many data types and integrating model predictions or ML backends into human labeling workflows.
- Preserve its primary placement under `model-and-data-platforms/dataset-curation`; ML-assisted labeling, pre-annotations, active-learning-style workflows, and model evaluation support extend the data-labeling product rather than making it a general MLOps platform.
- Preserve HumanSignal, Inc. (formerly Heartex) as the company that created Label Studio and continues to advance/support the open-source project.
- Distinguish the open-source Community Edition from Label Studio Enterprise and its hosted/cloud operating surfaces.
- Render the standard `entity-relations` block from the validated current-entity relation projection.
- Keep supported data/label types, ML backend architecture, enterprise-only capabilities, and other mutable details source-backed when expanded.
- Include current official Label Studio documentation, repository, and HumanSignal company references.

## Validation

- The page preserves Label Studio's data-labeling identity even when ML backends automate or assist annotations.
- HumanSignal's producer/maintainer role is not conflated with the separate Enterprise/cloud product boundary.
- Community and Enterprise/cloud capabilities are not conflated.
- The `entity-relations` block matches the validated current-entity relation projection and every rendered destination resolves to a canonical node.
- Official resource links match canonical entity metadata.
- The page contains no temporary-placeholder wording.
