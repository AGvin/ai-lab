# Documentation Requirements

## Requirements

- Identify TensorFlow as the end-to-end open-source machine-learning framework/platform originally developed at Google Brain and maintained through the TensorFlow Project.
- Preserve the core TensorFlow identity across tensor computation, automatic differentiation, neural-network/model training, distributed execution, data/input pipeline integration, and core deployment APIs while keeping separately branded ecosystem projects distinct.
- Keep Keras, TensorFlow Lite/LiteRT, TensorFlow.js, TensorFlow Serving, TFX, model repositories, and cloud/managed TensorFlow products with their own owners when independently useful.
- Treat stable language APIs, Python/C++ versions, CUDA/ROCm/DirectML/plugin support, OS/architecture support, package variants, build requirements, distributed strategies, release versions, and deprecations as freshness-sensitive.
- Preserve the distinction between stable releases and nightly packages.
- Attribute performance/scaling comparisons to exact release/backend/hardware/workload configuration.

## Validation

- TensorFlow remains the core ML framework rather than the entire TensorFlow ecosystem.
- Historical Google origin is not misrepresented as ownership of every downstream TensorFlow-branded project.
- Producer provenance resolves to TensorFlow Project.
