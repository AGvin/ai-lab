# Documentation Requirements

## Requirements

- Identify LangChain4j as a Java-oriented library/framework for integrating LLMs and vector stores into JVM applications.
- Preserve its two abstraction levels at a high level: lower-level model/vector-store primitives and higher-level AI Services for declarative application integration.
- Render the standard `entity-relations` block from the validated current-entity relation projection.
- Preserve tools/function calling, chat memory, streaming, structured output parsing, RAG, agents, and Java ecosystem integrations as framework capabilities without duplicating detailed tutorials.
- Keep provider/store inventories, integration counts, package versions, and other mutable ecosystem facts source-backed when expanded.
- Preserve the application-development primary role even though LangChain4j also exposes agent and RAG patterns.
- Include current official LangChain4j documentation and repository references.

## Validation

- The page does not imply identity equivalence with the Python/JavaScript LangChain framework merely from naming similarity.
- Agent and RAG capabilities do not duplicate canonical ownership of agent-first or retrieval-first framework profiles.
- Official resource links match canonical entity metadata.
- The `entity-relations` block matches the validated current-entity relation projection and every rendered destination resolves to a canonical node.
