# Documentation Requirements

## Requirements

- Identify Mirascope as a Python toolkit/library for building LLM-powered applications with provider-agnostic, type-oriented abstractions.
- Preserve model calls, reusable prompts, tools, structured outputs, streaming, async workflows, agents, context/chaining, local-model support, MCP, and observability as high-level capabilities.
- Keep provider inventories, API/version transitions, tracing backends, compatibility claims, and other mutable product state source-backed when expanded.
- Preserve the broader application-toolkit identity even though Mirascope includes agent-building capabilities.
- Include current official Mirascope documentation and site references.

## Validation

- The profile is not reduced to structured-output utilities alone.
- Agent capabilities do not automatically reclassify the broader Mirascope toolkit as an agent-first framework.
- Official resource links match canonical entity metadata.
