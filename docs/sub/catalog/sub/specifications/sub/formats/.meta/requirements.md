# Documentation Requirements

## Requirements

- Present Formats as the specification group for identifiable formal file, serialization, graph-exchange, model-artifact, and related data-format contracts whose normative identity belongs in the catalog.
- Create one canonical child per concrete selected format; do not create a generic `model-formats` specification artifact that duplicates the learning/concept grouping.
- For each concrete format, preserve authoritative specification identity, version/freshness boundaries, file/metadata/tensor or graph structure, normative types/fields/alignment/encoding rules, and conformance/compatibility semantics only to the depth supported by the upstream specification.
- Keep practical choosing/converting/validating guidance with learning, concrete runtime/product support with applicable software/service owners, and dated performance/quality findings with evidence/decision owners.
- Explain that the current materialized subset contains GGUF because its exact owner `catalog/specifications/formats/gguf/` is selected and current upstream specification material is available.
- Render standard direct-child navigation from only currently materialized concrete format nodes when rendering is activated.

## Validation

- The group is not used for generic model-format pedagogy or runtime compatibility matrices.
- Concrete format nodes cite authoritative/upstream specification sources for normative claims.
- Current navigation exposes only materialized children and does not imply that unmaterialized formats are absent from the selected architecture.
