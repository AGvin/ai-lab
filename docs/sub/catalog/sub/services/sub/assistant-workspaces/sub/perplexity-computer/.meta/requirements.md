# Documentation Requirements

## Requirements

- Present Perplexity Computer as Perplexity AI's released hosted general-purpose digital-worker/agent service for decomposing and executing multi-step work across research, analysis, coding, creation, connected applications, browser actions, scheduled/background work, and multiple model routes.
- Preserve its hosted execution boundary: Computer runs vendor-managed agent workflows and cloud execution even when it connects to user applications, files, browser state, or external services.
- Keep the general Perplexity answer/research workspace, Comet browser, Portable Computer local agent stack, API Platform, Skills Marketplace, and underlying model identities separate.
- Treat supported models, parallel-agent behavior, connectors, background/scheduled tasks, memory, generated artifact types, browser/computer-use capabilities, credit plans, subscription availability, limits, sandbox behavior, and data/retention controls as freshness-sensitive.
- Treat generated actions and connected-app side effects as permissioned external actions requiring scope/approval/review appropriate to the target system.
- Render the standard `entity-relations` block from validated current-entity relations.

## Validation

- Perplexity Computer remains a hosted service rather than the local Portable Computer software.
- Product identity is not collapsed into the generic Perplexity answer engine/workspace.
- Producer provenance resolves bidirectionally to Perplexity AI.
