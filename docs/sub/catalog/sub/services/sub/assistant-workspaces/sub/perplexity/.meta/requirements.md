# Documentation Requirements

## Requirements

- Present Perplexity as Perplexity AI's hosted assistant/workspace service spanning cited web answers, research, files/projects, multi-model orchestration, connected applications, and the current Perplexity Computer agentic-workflow surface.
- Preserve Perplexity Computer as a hosted agentic capability/product surface within the broader Perplexity end-user workspace identity unless upstream lifecycle establishes a separately necessary canonical service owner.
- Keep Perplexity API Platform and developer APIs separate from the end-user assistant/workspace identity; API access does not make the workspace a model provider or gateway.
- Keep Portable Computer separate as local/self-managed agent software because its agent harness, orchestrator, models, tools, queue, and sandbox execute on user-controlled hardware with optional approved cloud escalation.
- Treat exact plans, model routing, connector inventory, Computer capabilities, Projects/file limits, data handling, regional availability, subscription eligibility, and usage limits as freshness-sensitive.
- Preserve source/citation behavior as a product capability rather than a guarantee that every returned claim is correct or fully supported.
- Render the standard `entity-relations` block from validated current-entity relations.

## Validation

- Perplexity remains a hosted assistant/workspace service rather than a trained model identity.
- The hosted workspace is not conflated with Portable Computer's local execution boundary.
- Producer provenance resolves bidirectionally to Perplexity AI.
