# Documentation Requirements

## Requirements

- Present Kimi as Moonshot AI's hosted online assistant/workspace combining chat, web-connected search, deep research, multimodal reasoning, document/slides/sheets/web creation, general Agent mode, and Agent Swarm workflows.
- Preserve the hosted workspace boundary: Kimi web/mobile owns cloud-hosted chat and Agent execution, while Kimi Work owns local desktop agent execution, Kimi Code owns developer coding-agent workflows, and Kimi Claw owns always-online cloud automation/bot deployment.
- Keep Kimi model families, Kimi API, Kimi Code, Kimi Work, Kimi Claw, plugins/skills, and generated artifact types as separate model/product/integration boundaries rather than collapsing them into the hosted assistant identity.
- Treat current models, Agent/Swarm limits, tool inventory, memory, connected services, scheduled tasks, plans/credits, regional/mobile availability, data handling, and product features as freshness-sensitive.
- Render the standard `entity-relations` block from validated current-entity relations.

## Validation

- Kimi remains a hosted assistant/workspace service rather than a Kimi trained-model identity.
- Local Kimi Work/Code execution is not generalized into the hosted Kimi service.
- Producer provenance resolves bidirectionally to Moonshot AI.
