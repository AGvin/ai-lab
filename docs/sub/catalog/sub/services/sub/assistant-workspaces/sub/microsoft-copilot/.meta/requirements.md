# Documentation Requirements

## Requirements

- Present Microsoft Copilot as Microsoft's current unified hosted AI assistant/workspace application across web, Windows/macOS desktop and mobile, with experience shaped by personal versus work/school account and applicable Microsoft 365/Copilot entitlements.
- Preserve the current product boundary across chat, voice, search, library/create surfaces, file/content work, agents and Cowork/delegated work where available, without splitting each navigation surface into a peer service by default.
- Keep Microsoft 365 application integrations, Microsoft Copilot Studio, Microsoft Agent 365, underlying models/providers, Windows/Edge integration, and specialized product-specific Copilots with their own canonical owners when independently materialized.
- Preserve account/workspace-sensitive data and permission boundaries: consumer and Entra work/school experiences have different grounding, administrative controls, data protection and feature availability.
- Treat exact model choices, plans/licenses, Cowork/agent availability, application integrations, regional availability, UI/navigation, data controls, retention/training rules, discontinued features, and mobile/desktop behavior as freshness-sensitive.
- Render the standard `entity-relations` block from validated current-entity relations.

## Validation

- Microsoft Copilot remains a hosted assistant/workspace service rather than a trained model or Copilot Studio agent-building platform.
- Personal and managed-workspace data/control behavior is not conflated.
- Producer provenance resolves bidirectionally to Microsoft.
