# Documentation Requirements

## Requirements

- Identify Mistral Studio as Mistral AI's hosted developer console/platform for reusable prompt and skill assets, API keys, playground/testing, agent setup, model access, evaluations, usage monitoring, and related AI-application workflows.
- Preserve its primary catalog placement under hosted AI assets because Studio provides durable, versioned, shareable prompt/skill resources with workspace visibility and rollback semantics; note its broader developer-platform/API surface without duplicating every capability as a new service identity.
- Keep concrete Mistral model families, Vibe Work/Code, Admin, Libraries, Connectors, Search Toolkit/Agentic Search capability, and standalone API/model access concerns as separate identities or component surfaces when independently materialized.
- Treat plan availability, asset/version limits, API resources, supported models/features, Studio/Vibe integration, workspace permissions, and beta/GA state of individual capabilities as freshness-sensitive.
- Render the standard `entity-relations` block from validated current-entity relations.

## Validation

- The entity remains the hosted Studio product rather than a concrete model, skill collection, or generic prompt concept.
- Agentic Search is treated as a Studio/Search Toolkit/Libraries capability unless Mistral establishes a separate durable product identity.
- Producer provenance resolves to Mistral AI.
