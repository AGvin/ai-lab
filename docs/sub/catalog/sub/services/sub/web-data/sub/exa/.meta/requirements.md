# Documentation Requirements

## Requirements

- Present Exa as a producer-operated web search and retrieval service designed for AI applications and agents.
- Cover current first-party search/retrieval surfaces only where useful for distinguishing Exa from generic model APIs or browser-execution infrastructure.
- Keep SDKs, MCP integrations, and agent-framework integrations as product surfaces of the same service unless they acquire independent durable identity.
- Treat endpoint inventory, limits, pricing, indexing/coverage claims, and ranking behavior as freshness-sensitive.
- Keep models or external content returned through the service with their canonical owners rather than treating them as Exa-produced assets.
- Render the standard `entity-relations` block from validated current-entity relations.

## Validation

- Exa remains classified under hosted web-data services rather than model APIs or browser infrastructure.
- Mutable API and corpus claims are time-scoped when stated.
- Producer provenance resolves to Exa Labs, Inc.

## Scoped original-source qualification — 2026-11-06

- Exa's hosted web API provides programmatic semantic/keyword retrieval via search, content fetching and answer-oriented endpoints; its first-party current documentation also lists agent runs, Websets and monitored search experiences as additional product surfaces, not guaranteed independent canonical providers or trained model authors.
- The documented Search API accepts query, result filtering, text/highlight retrieval and API-key authentication. Source indexing/coverage, ranking, result quality, freshness, extract availability, webset access and agent quotas are account- and endpoint-dependent rather than a uniform crawler or universal browser-sandbox contract.
- Third-party web content, site copyrights and personal data remain attributed to original publishers. Hosted search snippets, summaries or agent results are not proof of independent source accuracy, compliant re-use rights, or unlimited indexing permission.
