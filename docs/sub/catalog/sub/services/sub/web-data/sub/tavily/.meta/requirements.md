# Documentation Requirements

## Requirements

- Present Tavily as a hosted web-data platform/API designed for AI applications and agents, with search and web-content retrieval/extraction as its primary catalog identity.
- Cover current first-party Search, Extract, Crawl, Map, or research-oriented API surfaces only while they remain part of the Tavily service.
- Keep Tavily distinct from managed browser infrastructure: its canonical value here is returning web/search/retrieval data rather than leasing a browser session as the primary primitive.
- Treat API limits, pricing, supported parameters, endpoint inventory, and coverage claims as freshness-sensitive.
- Do not create separate service nodes for each Tavily endpoint solely because the API exposes separately named operations.
- Render the standard `entity-relations` block from validated current-entity relations.

## Validation

- Classification remains web-data service rather than browser infrastructure or generic model API.
- Mutable API details are source-backed and time-scoped when stated.
- Producer provenance resolves to AlphaAI Technologies Inc.
