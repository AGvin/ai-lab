# Documentation Requirements

## Requirements

- Classify Linkup as a production web search/retrieval and multi-source research API for AI agents, with provider-hosted Search, Fetch, Research and Tasks interfaces. Keep each API workflow/mode within one canonical hosted platform rather than multiplying equivalent service identities.
- Distinguish Search's sourced links and snippets, Fetch's page content, Research's longer synthesis/citations, and Tasks' asynchronous bulk orchestration. The Extract endpoint is explicitly CLOSED BETA in current first-party API documentation and must not be stated as a stable generally available capability.
- Preserve the optional Bring Your Own Cloud/private index enterprise deployment boundary without automatically creating a separate installable software identity; verify service-provider data access, residency and licensing by plan.
- Do not treat publisher-reported benchmarking or alpha Flash mode performance as independently measured user recommendations. Keep data freshness, accuracy, custom indexes, API interface, cost and regional operations version-dependent.
- Keep Linkup's retrieved/cited evidence distinct from facts independently verified from the original sources; credit external source ownership and observe site/content access rights.
- Preserve first-party Linkup producer identity and reciprocal provenance.

## Validation

- Official first-party product/documentation sources demonstrate a released hosted operator service.
- `produced-by` and producer `produces` links are an exact inverse pair.
- Material beta, deployment or third-party content attribution boundaries are preserved.
