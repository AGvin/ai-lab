# Documentation Requirements

## Requirements

- Present `web-data/` as the service catalog owner for producer-operated APIs whose primary identity is supplying AI applications and agents with web search, retrieval, extraction, crawling, mapping, research, or browser-derived web data.
- Keep managed browser/session execution platforms under `services/infrastructure/` when their primary identity is remote browser infrastructure rather than data retrieval.
- Keep complete self-managed crawler/search software under `catalog/software/`.
- Link every materialized direct child exactly once and keep mutable endpoint/pricing/coverage claims with concrete child profiles.

## Validation

- Children are hosted web-data services rather than generic browser infrastructure or self-managed software.
- Navigation matches materialized direct children and every destination resolves.
- The category does not become a catch-all for ordinary SaaS APIs unrelated to agent/web data access.
