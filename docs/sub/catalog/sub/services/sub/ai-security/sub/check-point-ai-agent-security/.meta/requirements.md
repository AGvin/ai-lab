# Documentation Requirements

## Requirements

- Present Check Point AI Agent Security as the broad current agent-security product for discovering agents, assessing risk, and enforcing runtime controls over prompts, tools, data, and actions.
- Treat AI Guardrails as a runtime-protection component/tier of the current broader product surface rather than an automatic peer canonical entity.
- Treat supported platforms, discovery coverage, risk controls, Guardrails packaging, availability, and commercial claims as freshness-sensitive.
- Render the standard `entity-relations` block from validated current-entity relations.

## Validation

- The entity remains security-first rather than identity/governance-first.
- Producer provenance resolves to Check Point.

## Scoped original-source qualification — 2026-11-06

- Check Point's AI Agent Security service profiles agent discovery/inventory, context-sensitive risk assessment and inline runtime policy enforcement for prompts, tools, MCP servers, connected data and agent actions. These are documented platform features rather than independent guarantees that every agent or data flow is covered.
- AI Guardrails and Lakera Guard reflect protection technology/components; their docs should not be treated as a second independently accepted Check Point service identity solely because the broader platform uses them. Inline coverage depends on supported integration points, policy placement, account packaging and active versions.
- Publisher claims about preventing prompt injection, detecting off-policy actions, mitigating leakage, and working across AI providers are not equivalent to independently tested detection coverage, authorization or compliance.
- Verified first-party source 1: https://www.checkpoint.com/ai-security/ai-agent-security/
- Verified first-party source 2: https://docs.lakera.ai/guard
- Accept only source-bounded existing service identity and documented protection/deployment boundaries. This is not an independent security/privacy/compliance evaluation, vulnerability test, model validation result, new metadata/entity, reader repair, root-wide schema/cache/CI/render, clean pass, final delivery or merge.
