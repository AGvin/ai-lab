# Documentation Requirements

## Requirements

- Identify Microsoft Agent 365 as Microsoft's generally available enterprise control plane for discovering, observing, governing, and securing agents across an organization.
- Preserve its primary identity as an AI-management/governance service even though identity, security, compliance, observability, registry, and lifecycle capabilities are integrated into the product.
- Keep Microsoft Entra Agent ID, Windows 365 for Agents, Microsoft Copilot Studio, individual partner agents, and other independently durable Microsoft products as separate canonical identities.
- Treat plan eligibility, licensing, integrations, supported agent sources, security features, and administrative workflows as freshness-sensitive.
- Render the standard `entity-relations` block from validated current-entity relations.

## Validation

- The entity remains management/control-plane-first rather than being reclassified as an identity, security, or assistant-workspace product.
- General availability is scoped to the current Microsoft product evidence rather than generalized backward to preview periods.
- Producer provenance resolves to Microsoft.

## Scoped original-source qualification — 2026-11-06

- Microsoft's Agent 365 official documentation says the organization-wide agent registry, lifecycle governance, visibility, access, and data/security administration product became generally available to commercial customers on May 1, 2026. As published, at least one eligible per-user Agent 365 license is required to activate Agent 365, with additional eligibility and Microsoft E5 recommendations.
- The centralized control plane integrates Microsoft 365 Admin Center, Entra agent identity, Purview data protection and Defender threat defense; those remain separately managed product/permission surfaces. Agent 365 is not the installable runtime, the agent creator Microsoft Copilot Studio, or Windows 365 for Agents hosted Cloud PCs.
- Agent registry counts, third-party telemetry, protection, role-based oversight and audit features require supported identity/agent source, correct licensing, tenant policy and connected services. Commercial GA does not imply universal regional availability or blanket autonomous write access.

- Source acceptance credits current governance/control service identity and bounded publisher claims, not name aliases as new entities, metadata or reader repairs, independent compliance/security/runtime verification, full freshness, root-wide schema/cache/CI/render, clean pass, final delivery or merge.
