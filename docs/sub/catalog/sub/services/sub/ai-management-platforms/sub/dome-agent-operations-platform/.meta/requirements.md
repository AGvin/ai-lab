# Documentation Requirements

## Requirements

- Identify Dome Agent Operations Platform as Dome Systems' generally available cross-runtime, cross-cloud agent operations and governance control plane.
- Preserve its AI-management identity: the platform combines an Agent Registry, MCP Gateway, LLM Broker, policy/authorization, guards, quotas, audit, webhooks, and management on one control plane, but those capabilities are components of the same product rather than automatic peer canonical services.
- Keep managed agents, tools, models, pools, gateways, integrations, SDK/CLI/MCP interfaces, and third-party runtimes/providers as resources or integrations rather than producer-owned product identities.
- Preserve current self-service/GA status separately from plan-specific production guidance: Free can be used for evaluation while paid plans target production use.
- Treat pricing, plans, limits, integrations, policy/guard capabilities, API/CLI/SDK surfaces, resource model, and availability as freshness-sensitive.
- Render the standard `entity-relations` block from validated current-entity relations.

## Validation

- The entity remains an agent-operations/governance control plane rather than a standalone registry, gateway, or model router identity.
- GA status is grounded in the 2026-09-05 first-party launch, not inferred from earlier private-access periods.
- Producer provenance resolves to Dome Systems.
