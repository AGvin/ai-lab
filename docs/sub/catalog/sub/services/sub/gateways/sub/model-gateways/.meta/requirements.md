# Documentation Requirements

## Requirements

- Present Model Gateway Services as producer-operated gateway offerings designed primarily around unified model access, routing, fallback, model/provider policy, and AI-specific traffic control.
- Keep general API-management services separate when model traffic is only one secondary capability.
- List every materialized direct child exactly once and keep provider/model/pricing/availability facts with child profiles.

## Validation

- Navigation matches the materialized direct children.
- The category does not own the underlying models or model providers reached through the gateway.
