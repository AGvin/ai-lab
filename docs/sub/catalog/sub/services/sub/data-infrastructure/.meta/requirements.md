# Documentation Requirements

## Requirements

- Present `data-infrastructure/` as the semantic service parent for producer-operated persistent operational AI data state consumed by running applications and agents.
- Distinguish live operational data infrastructure from offline/developmental data generation and curation, generic compute/deployment infrastructure, web-data acquisition, and AI asset publication/discovery.
- Keep concrete service entities under one of the validated direct-child owners rather than directly under this parent unless a future product cannot be truthfully classified by those primary-identity boundaries.
- Render the standard child-navigation block from the validated direct-child projection.

## Validation

- Materialized direct children are semantic ownership groups rather than implementation-detail buckets.
- The parent does not become a generic database, storage, retrieval, or data catch-all.
- Child navigation matches the validated materialized direct-child projection.
