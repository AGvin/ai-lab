# Documentation Requirements

## Requirements

- Present Zep as a managed agent-memory/context service centered on storing, deriving, and retrieving reusable context and temporal knowledge.
- Treat graphs, search, and storage mechanisms as implementation properties when memory/context is the primary product job.
- Keep generic vector-database comparisons and framework orchestration outside this factual profile.
- Treat APIs, limits, hosted architecture, pricing, and current memory/graph capabilities as freshness-sensitive.
- Render the standard `entity-relations` block from validated current-entity relations.

## Validation

- Zep remains memory/context-first rather than vector-search or agent-framework ownership.
- Producer provenance resolves to Zep.

## Scoped original-source qualification — 2026-11-07

- Zep provides managed agent memory and temporal context via its Graphiti-based knowledge graph; hosted API and self-hosted open-source components must not be conflated.
- Publisher sources: https://www.getzep.com/ and https://help.getzep.com/
- Qualification scope is the existing service identity and product boundary; no live API tests, licensing/security assurance, whole-repository clean pass or final delivery credit.
