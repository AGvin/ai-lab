# Documentation Requirements

## Requirements

- Present `memory-and-context/` as the canonical service owner for producer-operated products whose primary identity is persistent or reusable memory, temporal/context knowledge, context assembly, profiles, or long-lived user/agent state for AI applications and agents.
- Treat underlying vector, graph, relational, embedding, indexing, and search mechanisms as technical properties when memory/context is the primary product identity.
- Exclude general vector/search databases, complete agent frameworks/platforms, user-facing knowledge workspaces, and self-managed memory/context software.
- Apply the lifecycle gate independently from taxonomy fit; preview-only managed memory products remain deferred even when their canonical owner is clear.
- Link every materialized direct child exactly once and keep mutable pricing/limits/availability claims with concrete product profiles.

## Validation

- Children are memory/context-first services rather than generic retrieval systems or agent frameworks.
- Implementation storage mechanisms do not create duplicate placement.
- Navigation matches validated materialized direct children.
