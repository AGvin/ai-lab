# Documentation Requirements

## Requirements

- Present Hindsight Cloud as a released, producer-operated **multi-tenant managed agent-memory service** with its own API endpoint, account, metered usage, billing, team administration and operated infrastructure. Do not duplicate the self-hosted Hindsight software identity.
- Treat the common retain/recall/reflect engine, MCP, client SDKs, vector/graph search, model inference and memory banks as service capabilities, not automatically independent product or trained-model identities.
- Distinguish Cloud from **self-hosted Hindsight MIT software**, and separate Enterprise BYOC/on-premises/dedicated arrangements as edition/contract boundaries unless independently qualified as distinct products.
- Cite official Cloud introduction, service API integration, billing and deployment comparison. Preserve the documented endpoint `https://api.hindsight.vectorize.io` as version/context-scoped, not as a guarantee of account access.
- Keep pricing, free credits, token/call/storage metering, backup cadence, uptime/SLA, security claims, availability, model integrations and region/residency freshness-sensitive. The vendor's pricing page is not an independently audited contract.
- Surface tenant/bank access-control risks, sensitive retained memory, remote model processing, data export/deletion/retention, encryption, credential leaks, recovery, availability and untrusted retrieved facts. Require actual DPA/terms and permission checks before sensitive/regulated use.
- Do not assert SOC 2 coverage, universal data isolation, beneficial ownership, sanctions clearance, production performance or independently verified restore/DR from vendor marketing alone.
- Preserve a single canonical `produced-by` edge to Vectorize AI, Inc. and exact `produces` inverse; render standard `entity-relations` from validated canonical sources.
