# Documentation Requirements

## Requirements

- Present Zilliz Cloud as Zilliz's fully managed Milvus/vector-search service.
- Keep serverless, dedicated, BYOC, managed clusters, APIs, and Terraform support as service deployment/operation surfaces rather than peer entities.
- Treat plans, regions, limits, Milvus compatibility, pricing, availability, and performance claims as freshness-sensitive.
- Render the standard `entity-relations` block from validated current-entity relations.

## Validation

- Zilliz Cloud remains managed vector/search infrastructure rather than generic cloud infrastructure.
- Producer provenance resolves to Zilliz.
