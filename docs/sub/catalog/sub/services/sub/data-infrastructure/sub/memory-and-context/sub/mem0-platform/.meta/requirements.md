# Documentation Requirements

## Requirements

- Present Mem0 Platform as the producer-operated managed memory service distinct from Mem0 Open Source/self-managed software.
- Treat vector stores, graph services, rerankers, embeddings, and search as implementation/capability details when reusable agent/application memory is the primary identity.
- Keep self-managed Mem0 with the existing software memory/context owner rather than duplicating facts between service and software identities.
- Treat pricing, managed backend behavior, enterprise controls, limits, and availability as freshness-sensitive.
- Render the standard `entity-relations` block from validated current-entity relations.

## Validation

- Mem0 Platform remains classified under managed memory/context rather than vector-search or agent-framework ownership.
- Producer provenance resolves to Mem0.

## Scoped original-source qualification — 2026-11-07

- Mem0's managed Platform and self-hosted/open-source memory SDK are distinct deployment/product boundaries; memory extraction, search and graph integrations are capabilities, not separate hosted products.
- Publisher sources: https://docs.mem0.ai/platform/overview and https://mem0.ai/
- Qualification scope is the existing service identity and product boundary; no live API tests, licensing/security assurance, whole-repository clean pass or final delivery credit.
