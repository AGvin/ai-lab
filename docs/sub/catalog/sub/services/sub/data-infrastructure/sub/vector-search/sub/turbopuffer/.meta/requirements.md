# Documentation Requirements

## Requirements

- Present turbopuffer as a producer-operated object-storage-native search service for vector, full-text, sparse, hybrid, and filtered retrieval.
- Keep native embeddings, namespaces, BYOC/single-tenant options, and branching as service capabilities while search/retrieval remains primary.
- Treat regions, latency/scale benchmarks, pricing, recall claims, embedding models, and deployment options as freshness-sensitive.
- Render the standard `entity-relations` block from validated current-entity relations.

## Validation

- turbopuffer remains managed search infrastructure rather than a model API or generic database service.
- Producer provenance resolves to turbopuffer.
