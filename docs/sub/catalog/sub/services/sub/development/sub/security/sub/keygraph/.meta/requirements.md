# Documentation Requirements

## Requirements

- Identify Keygraph as Keygraph's proprietary hosted/commercial application-security platform, distinct from the open-source Shannon Local Agent.
- Preserve the platform boundary at a stable level: continuous source/application security analysis, exploit-validated testing, findings lifecycle, remediation/verification, integrations, and managed/self-hosted/enterprise deployment options belong to the Keygraph platform rather than the Shannon open-source identity.
- Preserve the important white-box/black-box distinction: Shannon Open Source is the narrower self-run source-aware white-box agent, while current Keygraph platform editions can provide broader black-box/grey-box and lifecycle capabilities according to current packaging.
- Preserve high-trust safe-use boundaries for active exploitation, repository/source access, application/test credentials, model-provider credentials, findings/evidence, remediation changes, CI/CD integrations, and production/staging separation.
- Do not freeze legacy pricing, plan names, feature packaging, active-developer definitions, or inference charges; these are mutable and require current source verification when used for decisions.
- Render the standard `entity-relations` block from the validated current-entity relation projection.
- Link the Shannon Local Agent profile where relevant to clarify the product boundary.
- Include current official Keygraph platform/editions references.

## Validation

- Keygraph is represented as a hosted development-security service, not installable software or a duplicate Shannon agent.
- Open-source Shannon limitations are not generalized to the commercial platform, and commercial capabilities are not attributed to Shannon.
- Active security testing includes an explicit authorization/isolation boundary.
- The `entity-relations` block matches the validated current-entity relation projection and every rendered destination resolves to a canonical node.
