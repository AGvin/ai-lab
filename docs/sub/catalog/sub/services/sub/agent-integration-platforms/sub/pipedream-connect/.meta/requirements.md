# Documentation Requirements

## Requirements

- Present Pipedream Connect as Pipedream's producer-operated integration platform for embedding authenticated app/tool access into AI agents and applications.
- Cover managed authentication, connected accounts, tool/action discovery and execution, and MCP-facing surfaces where current first-party documentation supports them.
- Keep the broader Pipedream workflow product and individual third-party app integrations distinct from this service identity unless separately materialized by their canonical owners.
- Treat supported app counts, MCP/tool inventories, limits, pricing, and beta/GA state of individual surfaces as freshness-sensitive.
- Do not create one catalog entity per connector, action, or MCP tool merely because Connect exposes it.
- Render the standard `entity-relations` block from validated current-entity relations.

## Validation

- Pipedream Connect is classified by its managed integration/authentication job rather than as an agent framework or generic API gateway.
- Third-party integrations are not attributed to Pipedream as producer-owned software.
- Producer provenance resolves to Pipedream, Inc.

## Scoped original-source qualification — 2026-11-06

- Pipedream Connect provides vendor-managed external account authorization, hosted connectors and tool/MCP execution with credentials injected per external user. The product describes hosted Connect Link, managed token refresh and proxy execution to third-party APIs. Its dynamic tool/application totals are marketing inventory counts, not verified individual integration safety or guaranteed compatibility.
- Check external-user binding, OAuth scopes, connected-account owner and Pipedream-managed execution policies before any agent action. Pipedream Connect is distinct from the broader workflow builder and from each external API's permission, availability and license; do not materialize every tool as a new catalog entity.
