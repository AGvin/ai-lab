# Documentation Requirements

## Requirements

- Identify Microsoft Copilot Studio as Microsoft's producer-operated SaaS platform for building, testing, publishing, operating, and managing AI agents and agentic workflows.
- Preserve its primary managed agent-platform identity under hosted infrastructure rather than classifying it as Microsoft Agent 365: Copilot Studio is the maker/runtime surface, while Agent 365 is the organization-wide agent control plane.
- Keep Microsoft 365 Copilot, GitHub Copilot, Microsoft Foundry, Power Automate, external A2A agents, and individual published agents as separate canonical identities or integrations where independently materialized.
- Treat harness availability, preview/GA status, channels, connectors, models, workflow formats, licensing/Copilot Credits, governance controls, and integrations as freshness-sensitive.
- Render the standard `entity-relations` block from validated current-entity relations.

## Validation

- The entity remains a hosted agent-development/runtime platform rather than an assistant workspace or generic AI-management control plane.
- Preview status of individual harnesses/features is not generalized to the mature Copilot Studio product identity.
- Producer provenance resolves to Microsoft.

## Scoped original-source qualification — 2026-11-06

- Microsoft's original Copilot Studio documentation presents a graphical low-code managed platform for designing, testing, publishing and operating enterprise agents, workflows and agent flows across data/connectors and channels. This hosted maker/runtime product is not Microsoft 365 Copilot, Microsoft Agent 365's cross-enterprise control plane, Microsoft Foundry or Power Automate itself.
- Current Microsoft guides distinguish GitHub Copilot, Customer Conversation, Copilot chat and standard harnesses as product-level agent behavior choices; their feature, entitlement, memory, model access and consumption/billing differ. Natural-language app creation and certain harness features have preview-level constraints rather than universal production support.
- External connector scopes, identity privileges, deployed-channel access, human handoff, analytics, evaluation and financial limits require the exact environment/license and governance configuration. Microsoft's marketing capability claims are not proof of general security or independently validated agent accuracy.

- Verified first-party source 2: https://learn.microsoft.com/en-us/microsoft-copilot-studio/agents-overview
- Gate scope is inherited source identity and current publisher-documented version/rights/operational boundaries, not independent production testing, full freshness/security/legal review, metadata or reader-repair credit, root-wide schema/cache/CI/render, clean pass, final delivery or merge.
