# Documentation Requirements

## Requirements

- Present Encord as a managed applied-AI data platform spanning ingestion, curation, annotation, review, export, and iterative evaluation/active-learning workflows.
- Keep model evaluation inside this profile when it closes the data-improvement loop rather than becoming the primary product identity.
- Distinguish working datasets/annotations from live application retrieval/context state.
- Treat supported modalities, storage integrations, annotation/evaluation capabilities, pricing, and package details as freshness-sensitive.
- Render the standard `entity-relations` block from validated current-entity relations.

## Validation

- Encord remains data-generation/curation-first.
- Producer provenance resolves to Encord.

## Scoped original-source qualification — 2026-11-06

- Encord's first-party documentation and current product materials describe a managed data-development loop: collection/ingestion, curation/embedding search, annotation, review/QA, evaluation/feedback and data export. Physical-AI and multimodal workflows can include video, LiDAR/3D, image, audio, text and specialized expert labeling, but availability and quality targets are project-specific.
- Deployment/model performance feedback and RLHF/active-learning evaluations are part of Encord's iterative data improvement services, not proof of a separately operated universal model benchmark or of Encord owning the upstream model or collected datasets.
- Customer data locality, expert access, multimodal annotation quality, security/compliance language, prices and throughput depend on the actual contract, modality, stored-data integration and validation workflow; publisher case-study gains are not independent benchmark evidence.
- Verified first-party source 1: https://docs.encord.com/solutions-documentation/applied-ai/data-lifecycle
- Verified first-party source 2: https://encord.com/data-as-a-service/
- Acceptance credits historical or current service identity and publisher-scoped data creation/handling boundaries only. It does not establish current Gretel hosting, redistributable data/model rights, new identity/metadata, independent privacy/compliance/security checks, full freshness, whole-repo schema/cache/CI/render, reader repair, clean pass, final delivery or merge.
