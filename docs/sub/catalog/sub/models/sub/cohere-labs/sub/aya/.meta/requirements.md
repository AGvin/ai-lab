# Documentation Requirements

## Requirements

- Preserve Aya as the model-family identity with produced-by Cohere Labs and the existing Aya 23, Expanse, Vision and Tiny Aya membership pairs, plus the original Aya 101 concrete model.
- Describe the four represented series and the direct Aya 101 model without copying their parameter, language, license or context aggregates into intrinsic family metadata.
- Aya 101 is the 13 February 2024 independently published `CohereLabs/aya-101` instruction model with about 13B parameters, text-to-text generation across 101 languages and Apache-2.0 weights. Its mT5-XXL-style T5 encoder-decoder architecture must not be confused with later Command-derived Aya series or a current hosted API model. Its official model card does not establish a standard supported context-window size. [Official release](https://cohere.com/blog/aya) [Model card](https://huggingface.co/CohereLabs/aya-101).
- Document Aya 23 as a separate 2024 source-backed research-weight series with 8B and 35B checkpoints, 23 languages, 8,192-token context, gated CC-BY-NC-4.0 rights and no implied hosted API availability.
- Explain that first-party datasets, benchmarks and research publications are different objects from the trained models.
- Use model-specific cards and current API documentation for concrete facts; do not repeat the initiative landing page's conflicting Expanse 101-language marketing claim.
- Preserve exact model and producer lineage when material training or co-production is documented, including cross-group relationships; do not invent a concrete `derived-from` node for Aya 101 from architecture equivalence alone.
- Realize the complete English reader with exact identity, cited decision/operational facts and valid canonical navigation; advertise localized readers only when present.
