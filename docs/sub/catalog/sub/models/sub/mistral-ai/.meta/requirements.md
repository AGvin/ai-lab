# Documentation Requirements

## Requirements

- Link translated pages only when their destinations are materialized and resolve.

- Identify this node as the Mistral AI model-domain view.
- Link the canonical producer profile and render all validated direct model-family children through the standard child-navigation block.
- Keep specialized checkpoints in their upstream family when first-party evidence establishes that relationship; Leanstral 1.5 remains a Mistral Small 4 specialization rather than a duplicate top-level family.
- Preserve current lifecycle state from first-party model docs: current GA models, Labs/public-preview models, deprecated models, and retired models must not be presented as equivalent availability states.
- Keep API pricing, hosted aliases, service-only features, Studio/Vibe product surfaces, and deployment-provider availability outside intrinsic model identity.
- Treat release inventory, current exact checkpoints, deprecation/retirement dates, licenses, hosted/open-weight boundaries, and family lifecycle as freshness-sensitive.

## Validation

- The page remains model-domain navigation/context rather than a duplicate company profile.
- Family links resolve to canonical model owners without duplicating their specifications.
- Specialized models are not promoted to peer families when upstream evidence places them inside an existing family.
- Deprecated or scheduled-for-retirement checkpoints are never described as the current recommended release when a first-party replacement exists.

## Source-backed profile

- Required reader orientation: This model-domain view groups model families produced by Mistral AI. Canonical organization identity remains on the Mistral AI producer page.
- Preserve this model-scoped fact: The catalog includes released general-purpose and specialist models, with historical entries retained where their identity or lifecycle remains useful. Each concrete page owns its supported model facts.

## Operational and interpretation boundaries

- Explain this boundary: Model weights, API lifecycle and deployment services are separate concerns. Mistral’s API distinguishes GA, public preview, deprecated and retired access; preview can change silently. [Serverless model lifecycle policy](https://docs.mistral.ai/inference/model-lifecycle)
- Explain this boundary: A model offered by a platform is not necessarily produced by that platform. Third-party hosted models retain their own producer identity. [Models overview](https://docs.mistral.ai/models)

- Keep source-reported capabilities distinct from application-level correctness, authorization and measured deployment performance.
