# Documentation Requirements

## Requirements

- Define software-development model selection by concrete task rather than a universal coding ranking.
- Cover the selected task families: generation/editing, understanding, debugging/repair, testing, review, security engineering, architecture, agentic software engineering, and development/reliability analysis.
- Preserve the useful legacy coding decision rule: start with the least expensive credible route that meets the required acceptance tier and escalate on repeated capability failures or unacceptable review/regression cost.
- Require evaluation of correctness, omissions, repository understanding, tool use, recovery, verification, retries, review effort, and cost per accepted result.
- Preserve the representative evaluation minimum from the legacy coding guide without preserving its dated quick-pick rankings.
- Link canonical model facts from `../../../reference/` and keep task findings in selection.
- Materialize more specific selected child nodes only when their shortlist, evaluation dimensions, or acceptance criteria materially differ.
