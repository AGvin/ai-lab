# Documentation Requirements

## Requirements

- Present `personal/` for individual personal, household, hobby, learning, gaming-PC, accessibility, privacy/offline, maker/edge, personal-data, and home-lab contexts where one person primarily owns the decision and operation.
- Start from the person's actual tasks, existing devices, budget, administration tolerance, privacy/data boundary, connectivity, and willingness to operate local services rather than assuming that personal use means consumer cloud or local inference by default.
- Keep personal and professional routes distinct when workplace data handling, approved-tool policy, client confidentiality, or organizational administration materially changes the decision.
- Distinguish experimentation from persistent home-lab operation when uptime, remote access, service security, storage, backups, power, and maintenance become material constraints.
- Treat existing gaming GPUs, Apple unified memory, SBCs, edge accelerators, and other owned hardware as measured constraints rather than purchase recommendations or guarantees of model fit.
- Navigate only materialized direct-child scenarios and keep the group page concise; detailed routes, model candidates, trade-offs, and escalation triggers remain with the applicable scenario child.

## Validation

- Every materialized child is an individual-owned context rather than a professional, team, or organization-wide workflow.
- Privacy, budget, hardware, or local/cloud preference alone does not create a duplicate child unless it materially changes the route or evaluation contract.
- The page does not become a monolithic personal recommendation table or create placeholders for approved but unauthored scenarios.
