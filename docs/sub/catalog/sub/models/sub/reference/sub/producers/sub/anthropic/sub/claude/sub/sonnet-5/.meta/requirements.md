# Documentation Requirements

## Requirements

- Identify Claude Sonnet 5 as a concrete hosted model in the Claude family.
- Preserve exact model/API identity and intrinsic hosted-model facts from the legacy Sonnet 5 page.
- Keep pricing, plan availability, cloud-platform rollout, migration procedures, sampling-parameter compatibility, tokenizer migration, and workload-specific selection conclusions outside the canonical model profile.

## Content Specification

- Use `Claude Sonnet 5` as the page title.
- Link the canonical Claude family.
- Preserve the model ID `claude-sonnet-5`.
- Preserve the hosted Anthropic API access form as part of the exact model identity boundary without turning Claude Platform, Claude Code, Anthropic plans, or supported cloud platforms into model aliases.
- Preserve the documented 1,000,000-token context window and 128,000-token maximum output.
- Preserve adaptive thinking as the documented default reasoning mode.
- Present strong coding, planning, multi-step tool use, browser/terminal interaction, computer use, and long-horizon task handling as provider-described model positioning rather than independent AI Lab quality evidence.
- Include the official Sonnet 5 announcement and platform change documentation.

## Excluded Residual Content

Preserve outside this canonical model profile:

- input/output/token pricing and any time-bounded pricing observations;
- availability across Claude Platform, Claude Code, Anthropic plans, Amazon Bedrock, Google Vertex AI, or other product/deployment surfaces;
- migration guidance from previous Claude models, including replacement of manual extended thinking with adaptive thinking and effort controls;
- sampling-parameter compatibility details such as behavior of non-default `temperature`, `top_p`, or `top_k`;
- tokenizer-change guidance and any resulting token-count migration impact;
- Priority Tier or other service-tier availability;
- model-selection, cost, latency, reliability, coding-quality, tool-use, and accepted-result conclusions requiring separate evidence.

## Validation

- Product/deployment surfaces are not treated as aliases of Claude Sonnet 5.
- Pricing and service-tier state are not treated as stable model identity.
- Provider positioning is not presented as independent benchmark evidence.
- The page does not generalize Sonnet 5 behavior to the whole Claude family.
- The `member-of` relation resolves to the canonical Claude node.
