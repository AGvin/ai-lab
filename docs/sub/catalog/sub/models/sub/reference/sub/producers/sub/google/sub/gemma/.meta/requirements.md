# Documentation Requirements

## Requirements

- Identify Gemma as Google's open-weight language and multimodal model family for local, self-hosted, edge, research, and application workflows.
- Preserve family-level identity and deployment boundary from the legacy Gemma documentation without duplicating generation or concrete-model specifications.
- Keep exact parameter counts, modalities, context lengths, licenses, artifacts, runtime behavior, and deployment fit on generation/concrete model/artifact pages.
- Preserve source-specific Google DeepMind attribution on Gemma 4 rather than replacing it silently with the broader Google producer relation.

## Content Specification

- Use `Gemma` as the page title.
- Link Google through the current canonical `produced-by` relation.
- Describe Gemma as an open-weight family distinct from provider-hosted Gemini identities.
- Link Gemma 4 as the represented generation.
- Preserve the family-level instruction that exact generation, concrete model, variant, artifact, runtime, precision, and modality configuration must be recorded for evaluations.
- Include official Gemma documentation and the Google Hugging Face organization.

## Excluded Residual Content

Model-selection guidance, hardware fit, runtime performance, exact artifact compatibility, and evaluation conclusions belong to generation/concrete model, deployment/workflow, decision-support, or evidence owners rather than this family page.

## Validation

- Gemma is not treated as one exact deployment identity.
- Gemini hosted products are not conflated with Gemma open-weight models.
- Google DeepMind attribution on Gemma 4 is preserved at the source-specific generation level.
- Google producer and Gemma 4 links resolve to canonical nodes.
