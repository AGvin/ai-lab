# Documentation Requirements

## Requirements

- Identify Muse Spark 1.3 as a released current model identity in Meta's Muse family, introduced on September 2, 2026 and represented by Meta as its current Muse Spark model for agentic and coding work.
- Keep the trained-model identity distinct from Meta AI, the Muse personal-agent product, Muse Code, and the Meta Model API access surface.
- Preserve current multimodal, long-horizon agentic, coding, tool-use, and execution-environment capability claims only when supported by current first-party Meta sources.
- Keep benchmark scores, context limits, pricing, API regions/access, rate limits, model-routing aliases, and developer-access lifecycle freshness-sensitive.
- Preserve the existing Muse-family rule that a model can be canonical when it is released in a supported Meta product surface even if a particular developer API remains in public preview.
- Do not infer open weights or local/self-managed availability from Meta's product/API availability unless explicitly documented.
- Preserve family relation and current official resources during owner-authorized scoped repairs; bulk final rendering remains a separate phase.

## Validation

- Muse Spark 1.3 is not conflated with the Muse hosted personal-agent service.
- Public-preview API state is not misreported as preview-only model lifecycle when the model itself is released and deployed in current Meta products.
- Mutable benchmark/API/commercial claims retain current-source boundaries.

## Source precision

- Use the dated release announcement at https://research.meta.ai/blog/introducing-muse-spark-1-3 for introduction date and the model page at https://dev.meta.ai/models/muse-spark for current capability/access scope. Generic event and Llama landing routes are not the preferred evidence for this Muse model.
