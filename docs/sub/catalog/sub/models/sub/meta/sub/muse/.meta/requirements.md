# Documentation Requirements

## Requirements

- Identify Muse as Meta Superintelligence Labs' model family and keep distinct released Spark, media, speech, open-weight/local-agent, and Wonder-series model identities under their canonical children.
- Link Meta as canonical producer and materialize only released model or model-series identities supported by current first-party evidence.
- Exclude Muse Video while current first-party material still describes it as preview/coming-soon rather than a released peer.
- Keep Meta AI, Muse the hosted personal-agent product, Muse Code, Meta Model API, provider routes, and subscription/access state separate from trained-model identity.
- Treat API aliases, prices, regions, rate limits, and hosted availability as freshness-sensitive access facts rather than permanent family facts.

## Validation

- Released Muse model identities remain distinct from hosted products and access surfaces.
- Preview-only Muse Video is not materialized as a released peer.
- Open-weight licensing or self-hosting facts are not generalized from Muse Glimmer or Muse Spark Open to hosted-only siblings.
