# Documentation Requirements

## Requirements

- List only materialized concrete trained models in the GPT-Live family.
- Keep API routes, voices, transport options, and backend model pairings outside the concrete-model collection.

## Validation

- Every child is an independently identifiable model release rather than an API endpoint or product configuration.

## Source and navigation scope

- Derive membership from current materialized children and their canonical entity relations.
- Keep release-specific capability, lifecycle, and access claims on each model page.
