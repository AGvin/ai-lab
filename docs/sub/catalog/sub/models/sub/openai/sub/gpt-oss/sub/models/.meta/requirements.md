# Documentation Requirements

## Requirements

- Use Models as the page title and identify the parent model family.
- Treat this structural node as navigation, not a trained model, family, or model series.
- Render every eligible materialized direct child from the canonical tree, with its human-readable entity name.
- Keep model-specific identifiers, capabilities, lifecycle, and access boundaries on the concrete model pages.

## Validation

- All child links resolve to canonical model pages.
- The index contains no duplicate model profile or independent identity claim.
