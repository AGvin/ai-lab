# Documentation Requirements

## Requirements

- Identify Jev as TypeSafe AI's first public System One model, announced and released to early access on September 15, 2026.
- Preserve its primary first-party identity as a model for structured software decisions: application state plus typed questions produce typed probabilistic answers rather than free-form text.
- Describe Choice, Score, Noul, calibrated-probability behavior, RLCD, latency, cost, benchmark, and reliability claims only within their current first-party evidence boundary.
- Treat TypeSafe API aliases and revision identifiers such as `jev-latest` and returned version strings as mutable access/version state; do not create separate trained-model entities or versions without stronger first-party release evidence.
- Keep hosted APIs, third-party Jev services, pricing, quotas, SDKs, Agent Skills, and integration playbooks outside canonical model identity.
- Do not convert TypeSafe's statement that Jev cannot hallucinate strings into a general claim that Jev cannot make incorrect decisions.

## Validation

- Jev is not conflated with the TypeSafe AI organization or with a hosted provider/service.
- Vendor performance, calibration, reliability, and cost statements remain attributed rather than treated as independent AI Lab measurements.
- API aliases and mutable serving revisions are not misclassified as separate trained models.
