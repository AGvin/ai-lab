# Documentation Requirements

## Requirements

- Identify Gemini Omni as Google's multimodal generative model family combining Gemini reasoning/world understanding with generative-media capabilities.
- Materialize released concrete Omni models and keep preview serving routes outside the current released collection.
- Keep product integrations in Gemini, Flow, YouTube, Vids, and future API routes separate from trained-model identity.

## Validation

- Gemini Omni is not collapsed into the general Gemini family solely because it uses the Gemini brand; Google explicitly presents Omni as its own model family.
- Preview predecessor endpoints are not represented as current released peers.

## Verified identity and provenance

Google's multimodal generative-media family combining Gemini understanding with video generation and conversational editing; concrete model versions and product integrations are separate.

## Source-scoped operating boundaries

- The current stable API identity is Gemini Omni 1.1 Flash. Product availability in Flow or Gemini does not establish identical API controls, input modalities, or access rights. [Version-specific API reference](https://ai.google.dev/gemini-api/docs/models/gemini-omni-flash).
- Google documents residual edit-consistency, complex-motion, and text-rendering limitations and applies production filters and SynthID. Generated video should be reviewed for those failure modes; watermarking does not validate its factual content. [Omni model card](https://deepmind.google/models/model-cards/gemini-omni-flash/).
