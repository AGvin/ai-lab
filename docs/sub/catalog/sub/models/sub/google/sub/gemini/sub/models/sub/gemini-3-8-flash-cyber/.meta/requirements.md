# Documentation Requirements

## Requirements

- Identify Gemini 3.8 Flash Cyber as the GA, allowlisted cybersecurity-specialized Gemini 3.8 model variant documented by Google, distinct from the general Gemini 3.8 Flash model.
- Preserve the restricted-access boundary: current access is for trusted defenders through Google's Fairwind Program rather than general Gemini API availability.
- Keep cybersecurity specialization, access policy, and any current benchmark claims source-backed and time-scoped where mutable.
- Do not infer general-purpose superiority or ordinary public availability from the model's family membership.

## Validation

- Gemini 3.8 Flash Cyber is not collapsed into the base Gemini 3.8 Flash identity.
- Restricted access is not mislabeled as preview or experimental lifecycle status without source evidence.
- Mutable access and benchmark claims are not presented as timeless intrinsic facts.

## Verified identity and provenance

Google's cybersecurity post-training variant of Gemini 3.8 Flash, served as gemini-3.8-flash-cyber in GA behind a Fairwind allowlist.

## Source-scoped operating boundaries

- GA access remains allowlisted through Google's Fairwind program and subject to the cited Gemini Cyber service terms. It is not an unrestricted public Gemini API model. [Access and terms](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/3-8-flash-cyber).
- The Cloud model supports thinking, structured outputs, and caching. Function calling, code execution, grounding, computer use, Live API, Interactions API, and Batch are unsupported. General Flash features must not be copied onto this specialized endpoint. [Cyber capability matrix](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/3-8-flash-cyber).
