# Documentation Requirements

## Requirements

- Identify Adobe Firefly as Adobe's generative-media model family, distinct from the Firefly app/platform that can also host third-party models.
- Materialize current Adobe-trained model identities only when released/GA and independently useful.
- Keep Firefly product/workspace features, Creative Cloud integrations, partner models, Firefly Services APIs, custom models, plans, credits, and Content Credentials product behavior separate from intrinsic model identity.
- Treat model availability, API support, product integrations, credit accounting, custom-model support, and commercial-use policy as freshness-sensitive.
- Do not materialize Firefly Image Model 5 while first-party sources still label it public beta/preview under the current stable-only intake gate.

## Validation

- Adobe-trained Firefly models are not conflated with third-party models exposed through the Firefly product.
- Preview Image Model 5 is excluded until lifecycle evidence clears the gate.
