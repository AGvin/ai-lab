# Documentation Requirements

## Requirements

- Identify Cartesia as a developer and operator of real-time conversational speech technology. Distinguish the producer from its Cartesia Voice API, underlying Sonic/Ink model families, hosted Managed Agents workflows, third-party SDKs and generated voice artifacts.
- Ground claims in the [official overview](https://docs.cartesia.ai/get-started/overview) and [documented API](https://docs.cartesia.ai/api-reference/tts/bytes), not in unverified speed or accuracy rankings.
- Preserve one reciprocal `produces` / `produced-by` relation for the separately frozen Cartesia Voice API candidate. Do not create independent identities for all vendor models or voice-agent features solely because the API exposes them.
- Model versions, stream transports, supported languages, quotas, billing, output formats, regions, log retention, training-use restrictions and data controls are mutable vendor/service facts. An illustrative endpoint contract is not universal across all models or deployments.
- Synthesis, voice cloning, recordings and transcripts can involve personally identifiable or protected biometric, performance and copyright material. Require source-content authorization, consent where applicable, restricted API credentials and review of applicable processing terms before use.
- Do not infer unrestricted model-weight licenses, ownership of upstream third-party assets or permission to impersonate real speakers from a model-access interface.
- No authenticated inference, data upload, model benchmark, service/privacy audit, full CI or whole-catalog clean-pass claim.

## Validation

- The producer and the Cartesia Voice API reference one another through canonical catalog relations and resolved reader links; the Producers C index lists Cartesia exactly once.
- Current sources are cited for bounded claims without marking the whole entity as freshly audited.
