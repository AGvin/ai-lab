# Documentation Requirements

## Requirements

- Identify Microsoft as the canonical producer organization represented by the migrated Phi model documentation.
- Keep Phi family and concrete-model details in `catalog/models/` rather than duplicating them on the producer page.
- Keep Azure-hosted access, third-party inference providers, quantizations, runtime integrations, and deployment guidance with their corresponding service/software/artifact/workflow owners.

## Content Specification

- Use `Microsoft` as the page title.
- Describe Microsoft concisely as the producer organization for the documented Phi model family.
- Link the Microsoft model-domain view.
- Include the official Microsoft website and Microsoft Hugging Face organization as research references.

## Validation

- The page does not duplicate Phi or concrete model profiles.
- Hosted access and deployment properties are not generalized into producer identity.
- The model-domain link resolves to a canonical catalog node.
