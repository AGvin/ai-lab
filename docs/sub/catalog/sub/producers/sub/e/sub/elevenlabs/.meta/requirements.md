# Documentation Requirements

## Requirements

- Identify ElevenLabs as the producer of AI voice/audio technology and operator of its separately documented hosted developer API, not as an API-only model, one particular generated voice, an SDK or a distinct actor for every ElevenLabs application.
- Ground the producer identity in the current [official overview](https://elevenlabs.io/docs/overview/intro) and [API introduction](https://elevenlabs.io/docs/api-reference/introduction).
- Preserve the producer-to-hosted API `produces` relationship and inverse `produced-by` in the canonical ElevenLabs API node. The broader ElevenAgents or creative web experiences may be mentioned as adjacent provider offerings, not independently accepted frozen candidates in this batch.
- Treat specific voice models, API capabilities, model IDs, pricing, quotas, data retention, geographic availability and licensing tiers as mutable; do not assert immutable coverage or infer unrestricted rights to commercialize, clone or train on voices.
- Explain that recordings, cloned voices, speaker identities, audio files and transcripts may contain personal, biometric or copyrighted information. Use only appropriately authorized recordings and rights-cleared content, protect stored data and secrets, and review applicable consent and contract requirements.
- Avoid attributing models or voices of unrelated third parties to the provider merely because an API accepts or hosts them.
- No new global taxonomy, source-code license, complete legal/privacy audit, credentialed API calls, runtime benchmarking, full CI or whole-catalog clean-pass claim.

## Validation

- The producer and one ElevenLabs API service cross-link, and the Producers E index includes the producer exactly once.
- The current official documentation is referenced for source-scoped rather than complete freshness claims.
