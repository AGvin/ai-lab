## Requirements

- Identify Temporal Technologies Inc. as the company behind the Temporal open-source durable-execution platform.
- Preserve the project's Cadence/founder lineage as provenance while keeping Temporal Technologies, the open-source Temporal software, and Temporal Cloud as distinct layers.
- Render the standard `entity-relations` block from the validated current-entity relation projection.
- Include current first-party Temporal company, legal, and project-history references.
- Preserve this source-backed identity and provenance context: Temporal Technologies Inc. is the company behind the Temporal open-source durable-execution platform. Its founders' work on Cadence is historical provenance; Temporal, Cadence and the Temporal Cloud hosted service retain separate identities.
- Explain the following operating and decision boundary: Choose explicitly between operating the open-source Temporal Service and purchasing Temporal Cloud. Self-hosting requires deployment and long-term operational ownership; the Cloud terms define access, fees and support through the applicable service agreement and order. A local development server or evaluation account does not establish production readiness or the same support commitments.
- Support the producer context with these first-party sources: <https://temporal.io/about>, <https://temporal.io/terms-of-service>, <https://docs.temporal.io/self-hosted-guide>.

## Validation

- Temporal Technologies is not conflated with either the canonical Temporal software entity or Temporal Cloud.
- Cadence lineage is not represented as if Cadence and Temporal were the same current software identity.
- The `entity-relations` block matches the validated current-entity relation projection and every rendered destination resolves to a canonical node.
