# Documentation Requirements

## Requirements

- Identify TensorFlow Project as the current open-source project identity responsible for the TensorFlow framework.
- Preserve the historical fact that TensorFlow originated inside Google Brain separately from current project identity; do not infer a stronger current legal ownership relation than first-party governance material supports.
- Keep TensorFlow ecosystem libraries, Keras, TensorFlow Lite/LiteRT, TensorFlow.js, TF Serving, and downstream products separate when they have independently useful identities.
- Preserve this source-backed identity and provenance context: TensorFlow Project is the open-source project identity responsible for the represented TensorFlow framework. The upstream README records its origin with researchers and engineers at Google Brain; that history does not turn the project profile into Google's corporate identity.
- Explain the following operating and decision boundary: Evaluate the selected TensorFlow release and installation path, including supported language APIs, operating system and accelerator dependencies. Stable releases and nightly packages have different stability expectations. Keras, LiteRT, TensorFlow.js, TensorFlow Serving, TFX and hosted products retain their own release and support boundaries; core framework provenance does not guarantee compatibility across that ecosystem.
- Support the producer context with these first-party sources: <https://github.com/tensorflow/tensorflow>, <https://www.tensorflow.org/about>.

## Validation

- TensorFlow Project remains distinct from Google as an organization and from the TensorFlow software framework.
- Producer relation resolves to the canonical TensorFlow software node.
