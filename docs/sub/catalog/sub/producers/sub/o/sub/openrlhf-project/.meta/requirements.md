# Documentation Requirements

## Requirements

- Use the OpenRLHF Project/GitHub Organization as the direct producer identity for OpenRLHF.
- Do not infer a separate corporate producer from acknowledgements, infrastructure sponsorship, or historical organization names without authoritative evidence.
- Render the standard `entity-relations` block from validated current-entity relations.

## Validation

- `produces` is the inverse of OpenRLHF `produced-by`.

## Producer decision boundaries

- Describe the evidenced project publishing role without inferring incorporated status or exclusive sponsor ownership.
- Keep the framework code license separate from base-model, dataset, trained-weight, and compute-provider permissions.
- Render the official-resources block from canonical references supporting the producer identity and stated boundaries.

These boundaries are grounded in the first-party references recorded in the current entity. Detailed product behavior remains with each related artifact.
