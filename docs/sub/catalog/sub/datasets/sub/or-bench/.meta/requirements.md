# Documentation Requirements

## Requirements

- Treat OR-Bench as the over-refusal dataset family rather than a content-policy specification or unsafe-prompt generator service.
- Keep benign target intent, adversarial wording, original prompting context and evaluator rubric distinct.
- Preserve data revision, model version, user instruction context, scoring and refusal classifier for comparisons.
- Do not reproduce potentially unsafe prompt details, request live model access, or infer a full safety evaluation from over-refusal alone.
- No live generation, red-teaming, evaluator execution, comprehensive rights audit or whole-catalog clean pass performed.
- Ensure a unique frozen benchmark identity, pinned publisher sources and valid category link.

## Validation

- Confirm source and license boundaries; do not infer rights to hosted data or unperformed runtime verification.
