# Documentation Requirements

## Requirements

- Identify PaperBench as **OpenAI's original released 2025 research-replication benchmark dataset** comprising **20 selected ICML 2024 Spotlight and Oral papers** and **8,316 individually gradable rubric leaf criteria**. Rubric criteria are evaluation sub-tasks, not 8,316 distinct research papers, completed agent runs or separately accepted datasets.
- Describe each paper record as original PDF/Markdown, author addenda, necessary paper assets, the grading `rubric.json`, `blacklist.txt` (forbidden original-code/research sites), `config.yaml` and optional judge addenda, stored under `project/paperbench/data/papers`. Original source code/data live within the OpenAI `frontier-evals` repository; data use Git-LFS and are not hydrated by default. Do not infer independently verified size/hash/reproducibility of the entire LFS payload.
- Preserve **2025-04-02** original OpenAI publication and source revision boundary. The reviewed suite commit `b78dab1da774a6456b1ed9c48c9ff194ee3ff36d` contains current PaperBench README and `project/paperbench/pyproject.toml` package version `1.0.0`; do not present this package version as a verified standalone dataset release tag or proof that an April 2025 grader is identical to October 2026 main.
- Describe the three distinct evaluation stages: agent rollout in an isolated code workspace, execution of submitted replication code in a new GPU-capable environment, and rubric grading with the configured LLM judge. Model, agent scaffold, execution resources, paper files and rubric/judge revision jointly determine a score; older leaderboard entries are historical publisher claims, not independently reproduced AI Lab evaluations.
- Distinguish **PaperBench Code-Dev** as a lower-cost grading-protocol variant that skips code execution/results and focuses on code development, **JudgeEval** as an auxiliary judge-quality evaluation, and the **10-paper subset** used in some later OpenAI system cards as a subset with changed evaluation scope. None adds a new original PaperBench dataset identity. Distinguish OpenAI's existing **MLE-bench** Kaggle-competition engineering dataset from research paper replication.
- Preserve the actual [frontier-evals root MIT software/documentation license](https://github.com/openai/frontier-evals/blob/main/LICENSE.md) without assuming it grants third-party papers, copyrighted original paper figures/assets, linked LFS datasets or JudgeEval tarballs. The original PaperBench README explicitly states some JudgeEval tarballs cannot be automatically redistributed; access to ImageNet, Llama-2 and OpenAI/Hugging Face services can have independent licensing and credential restrictions.
- Highlight that original benchmark stages execute model/agent-created code, create Docker images and sometimes run untrusted code with GPUs, networks, tool permissions and remote API credentials. Require disposable isolated environments, pinned source/image/artifact revisions, restricted network/volumes/secrets, quota/budget controls, no privileged Docker socket on normal hosts, and no unrestricted third-party dataset redistribution. Do not instruct use of production credentials to grade untrusted submissions.
- Record explicit original OpenAI provenance with a single reciprocal `produced-by` / `produces` relation. Participating ICML paper authors co-developed rubrics but are not thereby independently accepted original PaperBench producer organizations. No full legal-rights, indirect ownership, model score replication or sandbox security audit has been performed.

## Validation

- Exactly one `catalog/datasets/paperbench` canonical dataset identity; no duplication of PaperBench Code-Dev, 20 individual papers, 8,316 rubric items, JudgeEval, model scores or MLE-bench.
- Original publisher/source/license refs and reciprocal canonical OpenAI producer links resolve, with new dataset-index navigation to materialized child.
- Scoped acceptance is not a claim of complete Git-LFS artifact hydration, reproducible execution, global current-head schema/cache/render/CI, full source/legal ownership clearance or either clean eight-root discovery pass.
