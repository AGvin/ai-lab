## Formal protocol residual

MCP defines versioned protocol contracts around messages, capabilities, lifecycle behavior, transports/bindings, authentication and authorization, extensions, conformance, and compatibility. Those contracts have changed materially over time.

Historical source material in this legacy page included a required initialization/session lifecycle and a fixed primitive/transport view. That wording is not retained as current canonical truth: the canonical MCP concept records the current protocol-evolution boundary, including the 2026 move away from the former required initialize/session model. Exact current methods, fields, message schemas, capability declarations, transports, extension identifiers, normative authorization behavior, deprecations, and conformance rules must be sourced from the applicable formal specification version.

Concrete MCP hosts, clients, servers, SDKs, registries, provider support matrices, implementation bugs, security advisories, and deployment configurations are likewise mutable catalog/platform/evidence material rather than timeless MCP semantics.
