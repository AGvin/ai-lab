# Архітектури моделей

Архітектура моделі описує організацію обчислень, компонентів та активації параметрів. Архітектура не залежить від масштабу моделі, способу розгортання, доступу чи положення відносно межі можливостей.

## Переклади

- [English](../../)
- Українська

## Активація параметрів

- [`dense-and-sparse-architectures/`](../../sub/dense-and-sparse-architectures/l10n/uk_UA/) — порівняння архітектур, які активують більшість параметрів, з архітектурами, які активують вибрані підмножини.
- [`mixture-of-experts/`](../../sub/mixture-of-experts/l10n/uk_UA/) — маршрутизація до вибраних експертних мереж, загальна кількість параметрів та кількість активних параметрів.

## Незалежні виміри

Позначення архітектури не можна використовувати замість інших властивостей моделі:

- Щільна архітектура не означає малу модель, а розріджена — велику.
- MoE не означає автоматично швидшу, дешевшу, практичну для локального запуску або frontier-модель.
- Квантування змінює числове подання, а не щільну чи розріджену архітектуру моделі.
- Проріджування може створювати розрідженість, але не є еквівалентом кожної архітектури з розрідженою активацією.
- Загальну кількість параметрів, кількість активних параметрів, резидентність у пам’яті та обчислення на токен треба записувати окремо, коли вони впливають на вибір.

## Використання під час вибору моделі

Використовуйте поля архітектури, коли вони пояснюють відповідність обладнанню, поведінку інференсу, пропускну здатність, вимоги до пам’яті, обмін між пристроями або сумісність із середовищем виконання.

Рекомендовані компактні значення:

```text
Architecture: Dense
Architecture: Sparse — MoE
Architecture: Unknown
```

Для MoE-моделі також окремо записуйте надійні значення загальної та активної кількості параметрів. Не порівнюйте її зі щільною моделлю, використовуючи лише одне з цих значень.
