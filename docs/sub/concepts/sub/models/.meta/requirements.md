# Documentation Requirements

## Requirements

- Present `models/` as the canonical concept domain for reusable knowledge about AI model classes, architectures, training and adaptation, inference, optimization and compression, interaction, behavior, and failure modes.
- Distinguish abstract model concepts from concrete model families, versions, artifacts, providers, and mutable model facts owned by `catalog/models/`.
- Distinguish conceptual model knowledge from model-selection recommendations and scenario-specific decisions; those remain with their selected decision owners.
- Explain that the model domain contains several orthogonal viewpoints rather than one single hierarchy of capability or quality.
- Render the standard direct-child navigation from the validated materialized child set when reader-facing rendering is activated.
- Keep the domain overview stable and conceptual; do not embed current-model rankings, prices, benchmark outcomes, or deployment recommendations.

## Validation

- The page does not present concrete model identities or current provider facts as concept-owned data.
- The page does not collapse classification, architecture, training, inference, optimization, interaction, and behavior into interchangeable dimensions.
- Direct-child navigation contains only currently materialized direct children and does not claim the full selected taxonomy is already implemented.
- The page does not duplicate model-selection guidance or time-specific evidence.
