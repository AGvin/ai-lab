# Documentation Requirements

## Requirements

- Use the reader-facing title `ML Systems Methodologies`.
- Present this group as reusable lifecycle methodologies for building, deploying, operating, monitoring, and evolving machine-learning systems as integrated production systems rather than isolated trained models.
- Keep `mlops/` as the selected direct descendant and do not infer additional methodology leaves merely because a vendor uses an `Ops` suffix.
- Distinguish ML-system methodology from model training algorithms, serving architectures, concrete platform products, and organization-specific operating procedures.
- Treat data, code, models, environments, evaluation, deployment, observability, lineage, governance, and feedback as potentially coupled lifecycle concerns without requiring every ML system to train or retrain models itself.
- Keep concrete pipeline engines, registries, cloud services, CI/CD implementations, monitoring products, and project runbooks with their applicable catalog or project owners.
- Render standard direct-child navigation from the validated materialized child set when reader-facing rendering is activated.

## Validation

- The group is lifecycle/system oriented rather than a duplicate model-training domain.
- Vendor-specific `Ops` labels do not automatically become canonical sibling methodologies.
- Direct-child navigation contains only materialized selected descendants.
