# Documentation Requirements

## Requirements

- Use the reader-facing title `AI Software Development Methodologies`.
- Present this group as software-development methodologies whose workflow is materially shaped by probabilistic model behavior, evaluation evidence, prompts/context, model/tool integration, and changing model capabilities.
- Keep `spec-driven-development/` and `eval-driven-development/` as the selected direct descendants; materialize only those with substantive current content.
- Distinguish methodology from generic SDLC/Agile/DevOps terminology and from concrete coding-agent products or project procedures.
- Explain that AI software development still uses ordinary software engineering controls for deterministic code while adding explicit evaluation and evidence loops where behavior cannot be specified or verified by conventional unit assertions alone.
- Keep project-specific acceptance gates, CI systems, prompt registries, model choices, and repository workflows with their applicable owners.
- Render standard direct-child navigation from the validated materialized child set when reader-facing rendering is activated.

## Validation

- AI-specific methodology value is explicit rather than relabeling generic software development.
- Selected child identities are not treated as mandatory universal processes.
- Direct-child navigation contains only materialized selected descendants.
