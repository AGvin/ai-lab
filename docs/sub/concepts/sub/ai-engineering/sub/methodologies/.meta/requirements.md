# Documentation Requirements

## Requirements

- Use the reader-facing title `AI Engineering Methodologies`.
- Present this domain as reusable engineering disciplines and lifecycle practices for developing, evaluating, operationalizing, and evolving AI-enabled systems.
- Distinguish a methodology from a product, one-off workflow, architecture pattern, model-training algorithm, or project-specific process. A methodology organizes recurring engineering work and evidence across a lifecycle rather than naming one implementation.
- Keep `software-development/` and `ml-systems/` as the selected direct methodology groups; materialize only descendants with substantive reusable content.
- Allow methodologies to compose ordinary software/DevOps practices with AI-specific evaluation, data/model/prompt lifecycle, reproducibility, deployment, monitoring, and feedback concerns without relabeling every generic software practice as AI-specific.
- Keep concrete tools, CI/CD products, deployment configurations, project runbooks, and task-specific process decisions with their applicable catalog or project owners.
- Render standard direct-child navigation from the validated materialized child set when reader-facing rendering is activated.

## Validation

- Methodologies are not reduced to tool lists or vendor recipes.
- Generic engineering practices are included only where their AI-system application forms part of a substantive reusable methodology.
- Direct-child navigation contains only materialized selected descendants.
