# Documentation Requirements

## Requirements

- Present the Documentation Tree as the exhaustive physical hierarchy of currently materialized RC documentation nodes.
- Mirror the implemented `catalog/` and `project/` documentation structure exactly, preserving parent/child nesting and relative links.
- Update the tree whenever a materialized documentation node is added, moved, or removed.
- Keep this page structural rather than descriptive; curated discovery belongs to Documentation Catalog.
- Do not list empty, removed, or merely planned placeholder branches.

## Validation

- Every listed link resolves to a currently materialized documentation node.
- Every currently materialized RC documentation node in the owned hierarchy is represented exactly once at the correct physical nesting level.
- Removed or placeholder-only nodes do not remain as stale tree entries.
- The page does not become a second curated catalog or duplicate long descriptions from entity pages.
