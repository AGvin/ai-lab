# Documentation Requirements

## Requirements

- Present Deep Learning as the Machine Learning learning group for multilayer learned representations, neural-network computation, gradient-based learning, training behavior, optimization, regularization, normalization, and representation learning.
- Keep architecture-specific model families with Models `architectures-and-representations/`; this group teaches reusable deep-learning principles that apply across architectures.
- Explain that the current materialized subset focuses on `neural-network-fundamentals/` because legacy neural-network material contains source-backed introductory computation/training/debugging guidance ready for migration.
- Do not imply that unmaterialized selected siblings `backpropagation-and-autograd/`, `optimization-for-deep-learning/`, `regularization-and-normalization/`, or `representation-learning/` are absent from the logical architecture; standard navigation reflects only physical children.
- Teach training behavior as dependent on data/input preparation, initialization, objective, optimizer/schedule, normalization/regularization, architecture, and numerical/resource conditions rather than one universal recipe.
- Treat parameter count, loss values, confidence scores, and model size as incomplete signals; route task quality, calibration, validity, and reliability claims to Evaluation and Research.
- Keep concrete framework commands, optimizer hyperparameters, dataset preprocessing recipes, model configurations, benchmark results, and hardware requirements with their applicable model/data/evidence/project owners.

## Validation

- Deep Learning is not used as a synonym for every neural network or every model architecture.
- Current navigation exposes only materialized selected children.
- Training/debugging guidance does not imply one architecture-independent configuration is universally stable or optimal.
- Evaluation/calibration claims remain with Evaluation and Research rather than being inferred from nominal model properties.
