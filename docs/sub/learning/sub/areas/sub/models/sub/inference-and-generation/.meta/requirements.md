# Documentation Requirements

## Requirements

- Present Inference and Generation as the Models learning group for executing trained/fixed models and controlling generation behavior, not for training parameters or operating complete production services.
- Teach the runtime path from model artifacts and execution preparation through device/runtime execution, context/memory behavior, decoding/generation controls, performance/capacity, and advanced inference techniques using the selected logical child structure.
- Keep deployment, service routing, autoscaling, fleet operations, and broader application/infrastructure lifecycle with AI Engineering; link them when they depend on model-execution knowledge.
- Keep formal artifact-format contracts, identifiable model/version facts, concrete runtime compatibility, and dated benchmark evidence with their catalog/specification/evidence owners.
- Explain that the current materialized subset includes `execution/` for model-format and CPU/GPU/offloading teaching, `context-and-memory/` for KV-cache/context-caching teaching, and `decoding-and-sampling/` for sampling-parameter/constrained-generation teaching.
- Do not imply that unmaterialized selected inference/generation branches are absent from the logical architecture; standard navigation reflects only physical children.

## Validation

- Inference/generation teaching is not conflated with model serving, deployment, training, or adaptation.
- Current navigation exposes only materialized children.
- Mutable runtime/provider support and formal format definitions are not stored as timeless learning truth.
