# Documentation Requirements

## Requirements

- Teach Language Modeling and Generation as modeling and generating linguistic/code sequences, independent from one model family or `LLM` size label.
- Use text generation, summarization, transformation, classification-like prompting, code-related work, structured tool-call generation, retrieved-document workflows, and natural-language instruction following as application examples without implying every model performs each equally well.
- Explain that applications commonly combine language models with prompts/instructions, retrieval, tools, state, validation, permissions, or other controls; those system components are separate from the model itself.
- Treat unsupported claims, exact calculations, bias, stale knowledge, and missing attribution as failure modes requiring task-appropriate validation rather than assuming fluent output is authoritative.
- Do not infer current private information, deployment location, runtime topology, or practical capability solely from a language-model or LLM label.
- Keep concrete model capability, context, latency, cost, runtime, hardware, license, and benchmark evidence source-backed with catalog/evidence owners.

## Validation

- Model output is not treated as database state or deterministic computation.
- System scaffolding remains distinct from model identity.
- Practical capability claims remain evidence-driven.
