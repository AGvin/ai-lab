# Documentation Requirements

## Requirements

- Teach Generative Architectures as model structures/processes that generate new samples, separate from concrete generation tasks and product workflows.
- Keep architecture-family mechanics distinct from modality/task learning: diffusion, autoregressive, adversarial, variational, and flow-based methods can support multiple modalities.
- Explain conditioning, latent/direct generation, iterative versus single-pass generation, and architecture/runtime consequences without turning concrete scheduler/model settings into universal rules.
- Link task-specific image/audio/video workflows from `modalities-and-tasks/` rather than duplicating them here.
- Keep concrete model identities, scheduler/runtime compatibility, dated benchmark results, and license terms with catalog/evidence owners.

## Validation

- Architecture mechanics are not conflated with image-generation task semantics.
- Concrete workflow settings remain implementation-specific unless a stable mechanism is being taught.
- Current navigation exposes only source-backed selected children.
