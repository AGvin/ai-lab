# Documentation Requirements

## Requirements

- Teach Security as adversarial compromise/manipulation risks affecting AI models, applications, agents, data, tools, and artifacts.
- Keep ordinary reliability/recovery mechanics with AI Engineering while Security owns hostile or deceptive inputs/actions and trust-boundary violations.
- This source-backed package materializes `prompt-injection/`; other selected security siblings remain logical until substantive content justifies physical creation.
- Teach defense in depth: model-facing instructions can guide behavior but consequential capabilities require application-level controls, validation, constrained permissions, isolation, or other external enforcement appropriate to the system.
- Keep concrete product security behavior, vulnerabilities, advisories, and current platform controls source-backed with their applicable owners.

## Validation

- System prompts are not presented as a standalone security boundary.
- Untrusted content remains distinguishable from governing application authority.
- Current navigation exposes only materialized selected children.
