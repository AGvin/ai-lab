# Documentation Requirements

## Requirements

- Present `areas/` as the subject-oriented canonical learning corpus selected by the AI Lab learning architecture.
- Organize learning primarily by the subject being learned, not by reader role, profession, beginner/intermediate/advanced labels, or one universal lifecycle.
- Explain that each area may use the internal pedagogical organization natural to that subject while preserving one canonical owner for each learning topic.
- Apply progressive depth within topics: plain-language orientation first, then prerequisites and intuition, rigorous mechanics, practice, design/configuration trade-offs, failure modes, evaluation/debugging, and advanced/current material where relevant.
- Prefer meaningful multi-level grouping over large flat sibling lists, but do not create wrapper nodes only for visual symmetry or speculative future content.
- Use cross-links for prerequisites and alternate journeys instead of duplicating content or distorting physical ancestry.
- Render standard direct-child navigation from only the currently materialized area nodes when rendering is activated; do not imply the complete logical architecture is already physical.

## Validation

- Reader expertise is treated as a quality test rather than a storage dimension.
- The page does not materialize or promise deferred learning paths.
- The implemented child set remains a faithful subset of the selected logical learning architecture.
