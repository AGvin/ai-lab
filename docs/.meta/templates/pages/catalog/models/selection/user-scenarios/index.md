# Model User Scenarios Index Page

## Description

Index page for the model user-scenario root and audience groups.

## Purpose

Help readers navigate from a combined real-world situation to a materialized scenario whose context genuinely changes the model route.

## Use When

Use for `catalog/models/selection/user-scenarios/` and its `personal/`, `professionals/`, `teams/`, and `organizations/` group nodes.

## Do Not Use When

Do not use for a concrete scenario leaf, task-oriented decision guide, hardware target, or canonical catalog entity.

## Owns

- the scenario method or audience-group boundary appropriate to the current node;
- concise explanation of dimensions that distinguish scenarios;
- validated child navigation;
- routing to sibling hardware selection when fixed hardware becomes the primary question.

## Does Not Own

- detailed recommendations belonging to child scenarios;
- canonical model/software/service/hardware facts;
- unmaterialized logical scenario destinations.

## Expected Inputs

Applicable root/group requirements and validated visible direct-child projection.

## Composition

1. standard header;
2. combined-context method or audience-group orientation;
3. key scope/data-boundary guidance;
4. child navigation;
5. concise sibling-route guidance when useful.

## Variants

- root index — method + four decision-scale groups;
- group index — one group boundary + materialized scenario children.

## Representative Examples

- `docs/sub/catalog/sub/models/sub/selection/sub/user-scenarios/`
- `docs/sub/catalog/sub/models/sub/selection/sub/user-scenarios/sub/personal/`

## Anti-patterns

- second recommendation monolith;
- empty scenario children created for symmetry;
- grouping primarily by local/cloud, privacy, budget, or VRAM instead of audience/decision scale.
